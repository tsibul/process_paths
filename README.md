# process_paths

Оцифровка путей: сущности, оси состояния, виды переходов, линейные варианты. Модель записывается в JSON, срезы вычисляет скрипт. Он проверяет модель, считает справочники и печатает её в Markdown. Чистый Python 3.14, без зависимостей.

## Вход: один JSON-файл на модель

- `texts`: тексты для печати. `title` — заголовок, `header` — строка под ним, `definitions` — определения (Markdown), `split_semantic` — проверка разделения по смыслу, `variants_note` — пояснение перед вариантами. Все поля необязательны.
- `existence_axis`: `{"name": "наличие", "absent": "не существует"}` — имя оси наличия и её значение для несуществующей сущности.
- `entities`: список сущностей `{name, axes: [{name, values, inherit?}]}`.
  - Первое значение в `values` — начальное.
  - Если сущность не существует, остальные её оси значений не имеют. При создании они получают начальные значения.
  - `inherit` — список пар `[сущность, ось]`. Созданная сущность берёт значение оси у первой пары, где оно есть; так задаётся место экземпляра, созданного из другого. Если значения нет ни у одной пары, ось получает своё первое значение.
- `kinds`: виды переходов `{name, entity, axis, from, to}`. Необязательные поля:
  - `cost` — стоимость: число значений, которые вид перехода устанавливает или решает;
  - `instrument_costs` — `{инструмент: число}`, стоимость для пары «вид + инструмент»;
  - `check` — признак «проверка», `true` или `false`;
  - `requires` — условие перехода: список `[сущность, ось, значение]` для других осей той же или другой сущности. Переход разрешён, только если в текущем срезе выполняются все пункты; иначе ошибка с вариантом и номером перехода.
- `executors`: исполнители `{name, factor?}`, где `factor` — коэффициент.
- `instruments`: список инструментов.
- `scopes`: охваты. `batch_scope` — какой из них означает «один раз на пачку».
- `variants`: варианты `{code, title, calls, entities?, initial?}`.
  - `calls` — переходы `[вид, исполнитель, инструмент, охват]` по порядку.
  - `entities` — состав сущностей варианта. Если поле не задано, это сущности, которых касаются переходы.
  - `initial` — отклонения начального среза: `{сущность: {ось: значение}}`.
- `forbidden_words`: запрещённые основы слов. `forbidden_exceptions`: фразы, которые убираются из текста перед поиском этих основ.

Срезы во входе не пишутся. Каждый переход меняет одно значение среза с «из» на «в». Если текущее значение другое или имя не из справочника, скрипт сообщает ошибку и называет вариант и номер перехода. Срез включает все оси всех сущностей варианта; у несуществующей сущности показывается только наличие.

## Запуск

Из папки проекта:

```
python -m process_paths <команда> модель.json
```

Команды:

- `check` — модель, прогон вариантов, разделение, запрещённые слова;
- `counts` — счёт справочников;
- `split` — проверка разделения: ни один вид перехода не повторяется цепочкой других видов по той же оси, одинаковых четвёрок «сущность, ось, из, в» нет;
- `variants` — для каждого варианта число переходов и задействованных видов;
- `unused` — незадействованные виды переходов и исполнители;
- `same` — одинаковые срезы между вариантами, полные и на общих осях; срез 0 — начальный;
- `cost [--batch N]` — стоимость пути на один документ и безопасность пути. Переход «на пачку» делится на размер пачки, по умолчанию 100. Дополнительно скрипт прогоняет размеры 1, 10, 100, 1000 и показывает, меняется ли порядок вариантов. Безопасность — число переходов с признаком «проверка»; от охвата она не зависит. Если числа не заданы, ни стоимость, ни безопасность не считаются;
- `markdown [-o файл]` — печать в Markdown. Изменившиеся значения выделяются жирным; при создании сущности выделяются её наличие и все оси, получившие начальные значения.
- `reach модель.json [модель2.json …] --goal "Сущность/ось=значение; Сущность/ось=значение" [--goals цели.json] [--base вариант] [--batch N] [--md] [-o файл]` — участки вариантов до цели.
  - Цель — набор значений осей. Она достигнута в срезе, где все эти значения выполняются.
  - `--goal` можно повторять. Файл `--goals` задаёт именованные цели: `{"имя": [["сущность", "ось", "значение"], …]}`.
  - Можно передать несколько моделей. Их справочники должны совпадать без учёта необязательных чисел, иначе ошибка. Варианты тогда подписываются `файл/код`.
  - Для каждого варианта выводятся: первый срез, где цель достигнута, или «не достигнута»; число переходов до цели с разбивкой по исполнителям и по охватам; стоимость участка по правилам `cost`; оси, сдвинутые к моменту цели, кроме осей самой цели; остаток — число переходов после цели.
  - Сдвинутой считается ось, значение которой в срезе цели отличается от отсчёта. Для сущности, существующей с начала, отсчёт — её значение в начальном срезе; для сущности, созданной на участке, — первое значение оси в справочнике. Поэтому унаследованное при создании значение, отличное от первого, считается сдвигом.
  - `--base` задаёт опорный вариант. Для каждого другого варианта выводятся оси, сдвинутые только у опорного, только у другого, у обоих одинаково и у обоих по-разному (значение у опорного / у другого). Сущность, которой нет в варианте, считается несуществующей.
  - `--md` даёт Markdown-таблицы по-русски.
- `norm модель.json --norm нормировка.json [--slices срезы.json] [-o файл.md] [--json файл.json]` — труд и пропуски по нормировке.
  - Нормировка: `kind_costs`, `executor_coefficients`, `scope_coefficients` — `{имя: число}`; `axis_skip_prices` — `{ось проверки: цена}`; необязательно `batch_size` и `uncounted_errors` — `{группа: [текст, …]}`. Имена должны совпадать со справочником модели; вид без стоимости, лишнее имя, ось проверки без цены, цена у оси, не являющейся осью проверки, ненулевая стоимость у вида с `zero_weight` — ошибка со списком всех расхождений.
  - Труд перехода = стоимость вида × коэффициент охвата × коэффициент исполнителя; труд варианта — сумма, по исполнителям и вместе.
  - Ось проверки — ось, которую меняет вид с `check: true`. Пропуск — ось проверки на первом значении (или без значения) в срезе.
  - Срезы: `{"имя": {"any": [{"states": [[сущность, ось, значение], …], "calls": [[вид, исполнитель], …]}, …], "otherwise": "final"}}`. Срез — первый, где выполняется хотя бы одна альтернатива: все её `states`, и, если задано `calls`, в варианте есть переход хотя бы одной из этих пар. `otherwise: "final"` — если срез не наступает, берётся конечный с пометкой. Пропуски считаются в каждом именованном срезе и в конечном.
  - Варианты с `out_of_comparison` считаются и помечаются «вне сравнения».
