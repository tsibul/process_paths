# process_paths

Оцифровка путей: сущности, оси состояния, виды переходов, линейные варианты. Модель записывается в JSON, срезы вычисляет скрипт. Он проверяет модель, считает справочники и печатает её в Markdown. Чистый Python 3.14, без зависимостей.

## Вход: один JSON-файл на модель

- `texts`: тексты для печати. `title` — заголовок, `header` — строка под ним, `definitions` — определения (Markdown), `split_semantic` — проверка разделения по смыслу, `variants_note` — пояснение перед вариантами. Все поля необязательны.
- `existence_axis`: `{"name": "наличие", "absent": "не существует"}` — имя оси наличия и её значение для несуществующей сущности.
- `entities`: список сущностей `{name, axes: [{name, values, inherit?}]}`.
  - Первое значение в `values` — начальное.
  - Если сущность не существует, остальные её оси значений не имеют. При создании они получают начальные значения.
  - `inherit` — список пар `[сущность, ось]`. Созданная сущность берёт значение оси у первой пары, где оно есть; так задаётся место экземпляра, созданного из другого. Если значения нет ни у одной пары, ось получает своё первое значение.
- `kinds`: виды переходов `{name, entity, axis, from, to}`. Необязательные поля:
  - `cost` — стоимость: число значений, которые вид перехода устанавливает или решает;
  - `instrument_costs` — `{инструмент: число}`, стоимость для пары «вид + инструмент»;
  - `check` — признак «проверка», `true` или `false`.
- `executors`: исполнители `{name, factor?}`, где `factor` — коэффициент.
- `instruments`: список инструментов.
- `scopes`: охваты. `batch_scope` — какой из них означает «один раз на пачку».
- `variants`: варианты `{code, title, calls, entities?, initial?}`.
  - `calls` — переходы `[вид, исполнитель, инструмент, охват]` по порядку.
  - `entities` — состав сущностей варианта. Если поле не задано, это сущности, которых касаются переходы.
  - `initial` — отклонения начального среза: `{сущность: {ось: значение}}`.
- `forbidden_words`: запрещённые основы слов. `forbidden_exceptions`: фразы, которые убираются из текста перед поиском этих основ.

Срезы во входе не пишутся. Каждый переход меняет одно значение среза с «из» на «в». Если текущее значение другое или имя не из справочника, скрипт сообщает ошибку и называет вариант и номер перехода. Срез включает все оси всех сущностей варианта; у несуществующей сущности показывается только наличие.

## Запуск

Из папки проекта:

```
python -m process_paths <команда> модель.json
```

Команды:

- `check` — модель, прогон вариантов, разделение, запрещённые слова;
- `counts` — счёт справочников;
- `split` — проверка разделения: ни один вид перехода не повторяется цепочкой других видов по той же оси, одинаковых четвёрок «сущность, ось, из, в» нет;
- `variants` — для каждого варианта число переходов и задействованных видов;
- `unused` — незадействованные виды переходов;
- `same` — одинаковые срезы между вариантами, полные и на общих осях; срез 0 — начальный;
- `cost [--batch N]` — стоимость пути на один документ и безопасность пути. Переход «на пачку» делится на размер пачки, по умолчанию 100. Дополнительно скрипт прогоняет размеры 1, 10, 100, 1000 и показывает, меняется ли порядок вариантов. Безопасность — число переходов с признаком «проверка»; от охвата она не зависит. Если числа не заданы, ни стоимость, ни безопасность не считаются;
- `markdown [-o файл]` — печать в Markdown.

Тесты: `python -m pytest`.
