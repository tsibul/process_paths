# Measure Twice: план устройства приложения

План, без кода. Приложение общего назначения: о предмете чужих моделей оно ничего не знает, все слова и числа приходят от пользователя. Пользователь файлов не читает и не правит: всё видит и вводит только в окне.

Слова плана: **справочник** — сущности, их оси и значения, виды переходов, исполнители, инструменты, охваты; **вариант** — линейная цепочка переходов; **срез** — значения всех осей в один момент; **нормировка** — числа: стоимость вида перехода, коэффициенты исполнителя и охвата, цена пропуска проверки; **вес** перехода — стоимость вида × коэффициент охвата × коэффициент исполнителя; **пропуск** — ось проверки, оставшаяся на начальном значении.

## 1. Как работает человек

### Версия 1. Загрузить и сравнить

1. Человек в разговоре с языковой моделью разбирает свой процесс: что меняется, какие есть варианты, какие числа.
2. Языковая модель по описанию формата готовит один файл проекта: справочник, варианты, нормировка.
3. Человек открывает приложение и загружает файл.
4. Если в файле ошибки, приложение показывает полный список замечаний. Человек копирует список языковой модели, получает исправленный файл и загружает его поверх.
5. Человек видит сравнительную таблицу: по каждому варианту — вес (всего и по исполнителям) и пропуски проверок с суммой цен. Таблицу можно сортировать, отбирать свои и чужие варианты, раскрыть вариант по шагам.
6. Справочник, варианты и нормировку можно посмотреть в окне, править нельзя.
7. Таблицу можно выгрузить в Markdown и CSV. Загруженные проекты остаются в списке.

### Версия 2. Графики

Рядом с таблицей — два графика, по линии на вариант, по горизонтали — номер шага. Человек видит, где по ходу пути варианты расходятся: где набирается труд и где делаются проверки.

### Версия 3. Править загруженное

Человек меняет в окне то, что загружено: числа нормировки, переходы в варианте, слова справочника; копирует вариант и меняет копию. Сравнение пересчитывается сразу. Ошибка правки показывается на месте, со строкой. Возвращаться к языковой модели ради одной цифры не нужно.

### Версия 4. Ручной ввод

Человек создаёт пустой проект и вводит всё в окне с нуля: справочник, варианты, нормировку. Языковая модель и файл не нужны.

## 2. Устройство

| Часть | Что делает |
|---|---|
| Ядро (есть, дорабатывается) | Проверяет проект, прогоняет варианты по шагам, считает вес и пропуски. Об окне и файлах не знает. Результаты не хранит |
| Файл проекта (новая) | Один файл JSON: справочник, варианты, нормировка. Загружается в базу целиком или не загружается вовсе; выгружается обратно |
| База (новая) | Все проекты пользователя в одном файле SQLite в папке данных. Ставить и настраивать нечего. Каждая правка записывается сразу |
| Окно (новая) | Список проектов и три вкладки: справочник; нормировка и варианты; сравнение. После переделок — четвёртая вкладка `Step chains`: пути как цепочки шагов человека с их переходами (`docs/decomposition_view_ru.md`). Сама не считает — все числа берёт у ядра. Подписи на английском |
| Выгрузка (частично есть) | Сравнение и подробности в Markdown и CSV |
| Командная строка (есть) | Те же проверка и расчёт без окна; нужна для сверки чисел с окном |
| Сборка (новая) | Готовая программа для Windows и Linux, запускается без Python |

Вид приложения — окно на компьютере пользователя (Python, PySide6). Причина: расчёт уже написан на Python; сети, сервера и учётных записей нет. Возражение: программу надо скачать, а неподписанная программа в Windows при первом запуске показывает предупреждение.

Что версия 2 рисует:

- **Цена по длине** — вес, накопленный после каждого шага. Вес каждого шага уже считается; не хватает только выдачи накопленной суммы по шагам.
- **Безопасность по длине** — сумма цен сделанных проверок на срезе после шага. Проверка сделана, если у оси проверки есть значение и оно не начальное; считаются все оси проверки справочника. Линия растёт, а опускается только там, где проверка откатилась на начальное значение. Вариант без проверок лежит на нуле. Проверки сейчас считаются только на именованных срезах и на конечном; не хватает счёта на каждом срезе.

Пути разной длины: по горизонтали номер шага, линия кончается на последнем шаге своего пути.

### Версия 6. Языки интерфейса

Языки по порядку: русский, греческий; исходный — английский. Переводятся окно, замечания
загрузчика и правки, заголовки выгрузки и отчёта PDF, просьбы к модели
(`measure_twice/data/ai_prompts_en.md`) и наставление для модели
(`measure_twice/data/ai_instructions_en.md` — единственный текст-инструкция, который программа
выдаёт пользователю; справки в окне нет, `docs/` с программой не идут). Не переводятся: содержимое
базы и файлы проектов, ключи и коды файла-ответа модели (`entities`, коды путей, `NO_JSON` и т. п.),
названия из проекта пользователя, командная строка (нужна для сверки чисел).

**Способ — только Qt, без новых библиотек.** В окружении PySide6 6.12.0 есть `QTranslator`,
`pyside6-lupdate`, `pyside6-lrelease`, `pyside6-linguist`. Тексты окна — через `self.tr()` /
`QCoreApplication.translate()`, числа со словом («3 ways») — формой `tr(текст, "", n)`: у русского
три формы множественного числа. Исходники переводов —
`measure_twice/i18n/measure_twice_<ru|el>.ts`
(XML, читается человеком, в репозитории); `.qm` собирает `pyside6-lrelease` при сборке и командой
для запуска из исходников, в репозиторий не кладутся. Готовые переводы стандартных окон Qt
(`qtbase_<lang>.qm` из `QLibraryInfo`) есть для `ru`, для `el` нет — поэтому у всех кнопок
программы свои подписи, стандартные `OK`/`Cancel` Qt не показываются; по-гречески подпись кнопки
выбирает перевод (например «Επόμενο», «Έξοδος»), а не Qt. Язык хранится в уже существующих
`QSettings("measure_twice", "measure_twice")`, ключ `language`; при первом запуске — язык системы,
если он из трёх, иначе английский. Даты и числа на экране — через `QLocale` выбранного языка. Шрифт должен покрывать греческий — проверяется в куске 32.
Ядро (`project.py`, `edit.py`, `export.py`) Qt не знает: замечание хранит английский шаблон
и подстановки, переводит окно при показе; шаблоны в ядре помечаются своей пустой функцией
`QT_TRANSLATE_NOOP`, чтобы их нашёл `lupdate` (что `lupdate` находит её без импорта Qt —
проверяется в куске 27).

**Объём (на 19.11, до кусков 15–24).** Строк окна в `measure_twice/ui/*.py` — около 180
(`pages.py` ~64, `app.py` ~44, `comparison.py` ~20, `ai_scenario.py` ~18, `chains.py` ~17,
остальные ~20); замечаний загрузчика `project.py` — около 90, правки `edit.py` — около 45;
заголовков выгрузки `export.py` — около 15. С кусками 15–24 (меню, окно вставки, отчёт PDF) —
ожидается 350–400 строк. Просьбы к модели — 216 строк, наставление — 342 строки, описание крана
`docs/example_tap_description_en.txt` — 11 строк.

**Просьбы к модели.** Переведённая просьба не проверена, пока на ней не прогнан пример крана:
для каждого языка переводится и описание крана, прогон делается как для английского, ответ должен
пройти загрузку без замечаний и совпасть с английским по составу (сущности, оси, пути и их коды).
Замечания загрузчика уходят модели на языке окна — это проверяется тем же прогоном.

**Таблица для заказчика.** Один файл HTML на язык (`docs/i18n/review_<lang>.html`), строится
из `.ts` — значит, на проверку идёт ровно то, что попадёт в программу. Столбцы: №, английский,
перевод, комментарий (синонимы, неточное соответствие, где стоит в окне). Почему HTML, а не `.md`:
открывается в любом браузере телефона без программ, длинные строки переносятся в ячейке;

- **process-64.** Новый вариант — кнопка `New` над списком путей на `Step chains`: код `New N`, название `New variant`, сторона `Ours`; всё правится в шапке (не на второй вкладке, как в 4.4 устройства). Да.
- **process-65.** В списке видов сначала допустимые, ниже `Not allowed here` и остальные серым с причиной; серые не выбираются. Да; заменяет process-48 («все виды»).
- **process-66.** Под строкой ввода перехода — срез `State here:`, пока строка открыта. Да.
- **process-67.** У варианта из окна нет шагов человека: `Steps not given`, переходы одним списком; ввод шагов — только если скажет заказчик. Да.
- **process-68.** `Batch size`, `Uncounted errors` и описание проекта в окне не вводятся. Да.
- **process-69.** Состав сущностей и отклонения начального среза — свёрнутый блок `Entities and initial state` под шапкой цепочки. Да.
- Решено без вопроса: пустой проект не пуст (три слова process-58: чтение требует непустых оси наличия и охвата «на пачку»); слово не переносится между сущностями и осями; сдвиг первого значения оси принимается (варианты могут получить `error`); вид правится целиком одной формой; правка вида молча убирает лишнее число нормировки (стоимость вида с «вес 0», цену оси, переставшей быть осью проверки); новый параметр варианта получает одного исполнителя у всех вариантов; после ошибки прогона в списке видов все виды без причин; списка ошибок справочника и счёта использования нет — вместо них перечень мест в отказе удаления и янтарная строка.
- Выгрузка из окна сверяется по содержимому (выгрузил, загрузил — тот же проект); совпадение текста с подготовленным файлом буква в букву не требуется (решение координатора). Тесты сравнивают `data`: справочник `tests/data/laundry.json`, набранный действиями окна в пустой проект; вариант «Б» «Стирки» без `steps`.
