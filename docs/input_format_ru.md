# procnorm: формат входного файла и правила заполнения

Документ адресован языковой модели, которая в разговоре с человеком готовит файл проекта. Человек файл не читает и не правит: он загружает его в приложение и видит результат в окне. Поэтому файл должен пройти проверку целиком; замечания проверки человек передаст тебе как есть.

## 1. Что описывает файл

- **Сущность** — то, у чего есть состояние. **Ось** — один независимый признак сущности. У оси — перечень **значений**.
- **Срез** — значения всех осей в один момент.
- **Вид перехода** — смена значения одной оси одной сущности: было «из», стало «в». Больше при переходе ничего не меняется.
- **Переход** в варианте — четвёрка: вид перехода, исполнитель, инструмент, охват.
- **Вариант** — линейная цепочка переходов. Развилок нет: развилка записывается двумя вариантами.
- **Нормировка** — числа. **Вес** перехода = стоимость вида × коэффициент охвата × коэффициент исполнителя. Вес варианта — сумма по переходам.
- **Проверка** — признак вида перехода. **Ось проверки** — ось, которую меняет такой вид. **Пропуск** — ось проверки, оставшаяся на начальном значении; у пропуска есть цена.

Приложение ничего не знает о предмете: все названия — твои, словами, на языке человека. Числа назначает человек; не придумывай их молча — предложи и спроси.

## 2. Общие правила

- Один файл JSON в кодировке UTF-8.
- Ссылка — это название, записанное буква в букву так же, как в месте, где оно объявлено (регистр, пробелы, «ё»).
- Числа — числами JSON (`2`, `0.1`), не строками.
- Порядок в списках значим: в этом порядке всё показывается, а первое значение оси — начальное.
- Необязательное поле, которое не нужно, не пиши вовсе.

## 3. Разделы файла

| Поле | Обязательно | Что это |
|---|---|---|
| `format` | да | Номер формата: `1` |
| `name` | да | Название проекта |
| `description` | нет | Одна-две фразы о проекте |
| `existence_axis` | да | `{"name": …, "absent": …}`: название оси наличия и значение «не существует». Пишется всегда, даже если ни у одной сущности такой оси нет |
| `entities` | да | Сущности с осями и значениями |
| `kinds` | да | Виды переходов |
| `executors` | да | Список названий исполнителей |
| `instruments` | да | Список названий инструментов |
| `scopes` | да | Список названий охватов |
| `batch_scope` | да | Один из охватов — тот, что значит «один раз на всю пачку» |
| `variant_params` | нет | Список названий параметров варианта |
| `named_slices` | нет | Именованные срезы с условиями |
| `variants` | да | Варианты |
| `normalization` | да | Нормировка |

### 3.1. Сущности: `entities`

```json
{"name": "Бельё", "axes": [
  {"name": "состояние", "values": ["грязное", "постирано", "убрано"]}
]}
```

- Названия сущностей не повторяются; названия осей не повторяются внутри сущности; значения не повторяются внутри оси.
- У оси есть хотя бы одно значение. **Первое значение — начальное.**
- Ось — один независимый признак. Если два признака меняются независимо, это две оси, а не одна с перечнем сочетаний.
- **Ось наличия.** Сущность, которая появляется или исчезает по ходу, получает ось с названием из `existence_axis.name`; среди её значений обязано быть `existence_axis.absent`. Если это значение первое, сущности в начале нет. Пока сущности нет, остальные её оси значений не имеют. При появлении они получают начальные значения, при исчезновении — теряют.
- `inherit` (необязательно, у оси): `[["Сущность", "ось"], …]` — откуда ось берёт значение в момент появления сущности: от первого источника, у которого значение есть и оно входит в значения этой оси; иначе — первое значение оси.

### 3.2. Виды переходов: `kinds`

```json
{"name": "Постирать", "entity": "Бельё", "axis": "состояние",
 "from": "грязное", "to": "постирано",
 "requires": [["Цикл стирки", "наличие", "есть"]]}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `name` | да | Не повторяется |
| `entity`, `axis` | да | Существующие сущность и её ось |
| `from`, `to` | да | Значения этой оси; `from` не равно `to` |
| `requires` | нет | Условие: список троек `[сущность, ось, значение]`. Переход возможен, только если все тройки выполнены в текущем срезе. Условие не ссылается на собственную ось вида |
| `check` | нет | `true` — вид является проверкой; его ось становится осью проверки |
| `zero_weight` | нет | `true` — переход остаётся в пути, но труда не несёт |
| `zero_weight_note` | нет | Причина; только вместе с `zero_weight: true`, непустой текст |

Правила:

- Вид — это смена состояния, а не действие определённого лица. Кто и чем делает, записывается в переходе. Поэтому **двух видов с одинаковыми сущностью, осью, «из» и «в» быть не может**.
- **Вид не должен повторяться цепочкой других видов по той же оси.** Если есть «а → б» и «б → в», вида «а → в» быть не может: один сдвиг записывался бы двумя способами. Нужен короткий путь — убери промежуточное значение или запиши оба шага.
- Появление сущности — вид по оси наличия из значения «не существует»; исчезновение — в это значение.
- Ось проверки удобно делать из двух значений: «не проверено», «проверено». Начальное — «не проверено».
- Оси проверки разных сущностей могут называться одинаково: цена пропуска записывается по паре «сущность, ось».

### 3.3. Исполнители, инструменты, охваты

Три списка названий, без повторов внутри списка.

- Исполнитель — кто делает: человек, программа, устройство.
- Инструмент — чем делает. В расчёт не входит, только описывает.
- Охват — на что приходится действие: на каждую единицу или один раз на всю пачку. `batch_scope` называет охват «на пачку».

### 3.4. Параметры варианта: `variant_params`

Параметр — названная роль, которую в каждом варианте занимает один из исполнителей. Нужен, когда условие среза зависит от того, кто эту роль занимает. Если такой зависимости нет, поле не пиши.

```json
"variant_params": ["получатель"]
```

Тогда у **каждого** варианта: `"params": {"получатель": "Человек"}`.

### 3.5. Именованные срезы: `named_slices`

Срез с именем — момент, на котором считаются пропуски. Задаётся условием; в варианте это первый срез, где условие выполнено.

```json
"named_slices": {
  "постирано": {"any": [
    {"states": [["Бельё", "состояние", "постирано"]]}
  ]}
}
```

- `any` — непустой список групп; достаточно одной выполненной группы («или»).
- В группе все строки выполняются вместе («и»). Строки — `states`: тройки `[сущность, ось, значение]`, и `params`: пары `[параметр варианта, исполнитель]`. Группа без строк недопустима.
- Конечный срез есть всегда, его не записывают. Название `final` занято.
- Если условие в варианте не наступило, срез совпадает с конечным.

### 3.6. Варианты: `variants`

```json
{"code": "Б", "title": "Быстрая стирка", "side": "other", "task": "Постирать бельё", "calls": [
  ["Запустить машину", "Человек", "стиральная машина", "вся загрузка"],
  ["Постирать", "Машина", "стиральная машина", "вся загрузка"]
]}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `code` | да | Короткий код, не повторяется |
| `title` | да | Название |
| `side` | нет | `"own"` — свой, `"other"` — чужой; без поля — свой |
| `task` | нет | Задача варианта: непустой текст, сравнивается как введён. Варианты с одинаковой задачей сравниваются друг с другом |
| `calls` | да | Переходы по порядку: `[вид, исполнитель, инструмент, охват]`, все четыре — из справочника |
| `params` | если есть `variant_params` | Исполнитель для каждого параметра |
| `entities` | нет | Список сущностей варианта. Без поля — сущности, которых касаются переходы |
| `initial` | нет | Отклонения начального среза: `{"Сущность": {"ось": "значение"}}` |
| `out_of_comparison` | нет | Причина, по которой вариант считается, но в сравнение не идёт; непустой текст |
| `steps` | нет | Шаги человека, на которые разложены переходы: `[{"text": …, "calls": …}, …]`. `text` — шаг его словами, непустой текст; `calls` — сколько переходов подряд из `calls` варианта к нему относятся, целое не меньше нуля. `calls: 0` разрешён: шаг без перехода. Сумма `calls` по шагам равна числу переходов варианта, иначе замечание «steps cover N calls, the variant has M» |

Прогон варианта — главное правило. Вариант исполняется по шагам от начального среза:

1. Начальный срез: у каждой сущности варианта каждая ось на первом значении (с учётом `initial`); у отсутствующей сущности значение есть только у оси наличия.
2. Для каждого перехода: текущее значение оси вида должно быть равно его `from`; все тройки `requires` должны быть выполнены. Тогда ось получает `to`.
3. Первый шаг, где это не так, — ошибка варианта.

Перед записью варианта пройди его по шагам сам, держа срез в уме.

### 3.7. Нормировка: `normalization`

| Поле | Обязательно | Правило |
|---|---|---|
| `kind_costs` | да | `{вид: стоимость}` — для каждого вида без `zero_weight`. У вида с `zero_weight` стоимость можно не писать; если написана — только `0`. Стоимость не меньше нуля |
| `executor_coefficients` | да | `{исполнитель: коэффициент}` — для каждого исполнителя. Тот, чей труд не считается (программа, устройство), получает `0`. Коэффициент не меньше нуля |
| `scope_coefficients` | да | `{охват: коэффициент}` — для каждого охвата. Коэффициент не меньше нуля |
| `axis_skip_prices` | да | `{сущность: {ось проверки: цена}}` — для каждой оси проверки и только для них. Цена больше нуля |
| `batch_size` | нет | Размер пачки, для которой даны коэффициенты охвата; справочное число |
| `uncounted_errors` | нет | `{группа: [текст, …]}` — ошибки, у которых нет своей оси; показываются списком, в счёт не входят |

- Лишних названий быть не должно: только те, что есть в справочнике.
- Вес считается на одну единицу. Если пачка — 10 единиц, обычная пара коэффициентов охвата: «на каждую» — `1`, «на пачку» — `0.1`.
- Единицу стоимости выбирает человек; она одна на весь проект.

## 4. Порядок работы

1. Выясни у человека процесс и варианты, которые он хочет сравнить; какие из них свои, какие чужие.
2. Выдели сущности и оси. Мелко не дроби: ось нужна, если её значение меняется хотя бы в одном варианте или стоит в условии.
3. Запиши виды переходов; отметь проверки.
4. Запиши шаги человека его словами по каждому варианту. Разложи каждый шаг на переходы и запиши `steps` рядом с `calls`. Шаг, который не дал перехода, не выбрасывай: запиши его с `calls: 0`.
5. Запиши варианты и прогони каждый по шагам. Поставь `task` каждому варианту: варианты с одинаковой задачей сравниваются друг с другом, вариант без задачи или с единственной задачей остаётся без пары.
6. Согласуй с человеком числа нормировки.
7. Перед выдачей файла покажи человеку цепочки текстом: по каждому пути шаги его словами, под каждым шагом его переходы; шаг без перехода пометь «нет перехода». Файл выдай только после того, как человек согласится с разбором.
8. Сверь файл со списком в разделе 5.

## 5. Типовые ошибки

Замечания проверка выдаёт на английском; названия в них — как записаны в файле. В таблице смысл замечаний пересказан по-русски. Файл с неполной нормировкой не загружается.

| Ошибка | Что скажет проверка | Что делать |
|---|---|---|
| Название в ссылке отличается от объявленного | неизвестная сущность, ось, значение, вид, исполнитель, инструмент или охват — с местом | Привести к одному написанию |
| Название повторяется | повтор — с названием | Переименовать или убрать |
| У вида `from` равно `to` | «из» равно «в» | Это не переход; убрать |
| Условие вида на его же ось | условие на собственную ось | Условие уже выражено в `from` |
| Два вида с одной сменой состояния | одинаковая четвёрка | Оставить один; различие — в исполнителе и инструменте перехода |
| Вид повторяет цепочку других | вид раскладывается — с цепочкой | Убрать короткий вид или промежуточное значение |
| Переход не из текущего значения | вариант, номер перехода: ось имеет одно значение, ожидалось другое | Пропущен или переставлен шаг |
| Условие не выполнено | вариант, номер перехода: условие не выполнено | Добавить недостающий шаг раньше |
| Переход по оси сущности, которой нет в варианте | сущность не входит в вариант | Добавить её в `entities` или убрать поле |
| Сущности ещё нет, а её ось меняют | ось не имеет значения, ожидалось «из» | Сначала переход появления |
| У оси наличия нет значения «не существует» | у оси наличия нет этого значения | Добавить значение |
| `batch_scope` не из списка охватов | охват «на пачку» не найден | Назвать существующий охват |
| У варианта не задан параметр | параметр варианта не задан | Задать `params` для каждого параметра |
| Нет числа в нормировке | вид без стоимости; исполнитель или охват без коэффициента; ось проверки без цены | Добавить число |
| Лишнее название в нормировке | стоимость неизвестного вида; цена оси, которая не ось проверки | Убрать |
| У вида `zero_weight`, а стоимость не 0 | вес 0, но стоимость задана | Поставить `0` |
| Число записано строкой | ожидалось число | Убрать кавычки |
| Отрицательное число; цена пропуска 0 | число вне допустимого | Стоимость и коэффициенты — не меньше нуля, цена пропуска — больше нуля |
| `task` пустой или не текст | `variant X: task must be a text` | Записать задачу непустым текстом или убрать поле |
| Срез назван `final` | название занято | Переименовать |

## 6. Пример целиком

Предмет — стирка одной загрузки белья, три варианта.

```json
{
  "format": 1,
  "name": "Стирка белья",
  "description": "Три способа постирать одну загрузку белья.",
  "existence_axis": {"name": "наличие", "absent": "нет"},
  "entities": [
    {"name": "Бельё", "axes": [
      {"name": "состояние", "values": ["грязное", "постирано", "развешано", "высохло", "убрано"]},
      {"name": "карманы", "values": ["не проверены", "проверены"]},
      {"name": "цвета", "values": ["не разобраны", "разобраны"]}
    ]},
    {"name": "Цикл стирки", "axes": [
      {"name": "наличие", "values": ["нет", "есть"]}
    ]}
  ],
  "kinds": [
    {"name": "Проверить карманы", "entity": "Бельё", "axis": "карманы",
     "from": "не проверены", "to": "проверены", "check": true},
    {"name": "Разобрать по цветам", "entity": "Бельё", "axis": "цвета",
     "from": "не разобраны", "to": "разобраны", "check": true},
    {"name": "Запустить машину", "entity": "Цикл стирки", "axis": "наличие",
     "from": "нет", "to": "есть"},
    {"name": "Постирать", "entity": "Бельё", "axis": "состояние",
     "from": "грязное", "to": "постирано",
     "requires": [["Цикл стирки", "наличие", "есть"]]},
    {"name": "Развесить", "entity": "Бельё", "axis": "состояние",
     "from": "постирано", "to": "развешано"},
    {"name": "Дождаться высыхания", "entity": "Бельё", "axis": "состояние",
     "from": "развешано", "to": "высохло",
     "zero_weight": true, "zero_weight_note": "ожидание, труда нет"},
    {"name": "Убрать в шкаф", "entity": "Бельё", "axis": "состояние",
     "from": "высохло", "to": "убрано"}
  ],
  "executors": ["Человек", "Машина"],
  "instruments": ["руки", "стиральная машина", "сушилка"],
  "scopes": ["каждая вещь", "вся загрузка"],
  "batch_scope": "вся загрузка",
  "named_slices": {
    "постирано": {"any": [{"states": [["Бельё", "состояние", "постирано"]]}]}
  },
  "variants": [
    {"code": "А", "title": "Аккуратная стирка", "side": "own", "task": "Постирать бельё", "calls": [
      ["Проверить карманы", "Человек", "руки", "каждая вещь"],
      ["Разобрать по цветам", "Человек", "руки", "каждая вещь"],
      ["Запустить машину", "Человек", "стиральная машина", "вся загрузка"],
      ["Постирать", "Машина", "стиральная машина", "вся загрузка"],
      ["Развесить", "Человек", "сушилка", "каждая вещь"],
      ["Дождаться высыхания", "Человек", "сушилка", "вся загрузка"],
      ["Убрать в шкаф", "Человек", "руки", "каждая вещь"]
    ],
    "steps": [
      {"text": "Достать порошок", "calls": 0},
      {"text": "Проверить карманы", "calls": 1},
      {"text": "Разобрать по цветам", "calls": 1},
      {"text": "Загрузить бельё и включить машину", "calls": 2},
      {"text": "Развесить бельё", "calls": 1},
      {"text": "Дождаться, пока высохнет", "calls": 1},
```
