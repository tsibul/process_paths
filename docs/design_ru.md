# Проект приложения procnorm

Документ — проект, без кода. Наполнение (справочник, нормировка, пути) вносится позже, когда закончатся работы над ними.

## 1. Назначение и границы

Способ, который приложение обслуживает:

- **сущность** — то, у чего есть состояние; у сущности есть **оси состояния**, у оси — перечень **значений**, первое — начальное;
- **срез** — значения всех осей всех сущностей варианта в один момент;
- **вид перехода** — вид перехода меняет значение одной оси одной сущности: было «из», стало «в». Больше ничего при переходе не меняется. У вида может быть условие: переход возможен, только если названные в условии оси уже имеют названные значения. Сами эти оси остаются как были;
- **проверка** — признак вида перехода; **ось проверки** — ось, которую меняет вид с этим признаком;
- **вес 0** — признак вида перехода с примечанием: переход остаётся в пути, его стоимость труда 0;
- **переход в варианте** — четвёрка: вид перехода, исполнитель, инструмент, охват; какой охват считается «на пачку», задаёт справочник;
- **параметр варианта** — названная роль, которую в каждом варианте занимает один из исполнителей справочника; кто именно, задаёт вариант (в нынешнем проекте — «получатель»);
- **вариант пути** — линейная последовательность переходов, без развилок; вариант может задать список своих сущностей, если список не задан, участвуют сущности, которых касаются переходы варианта;
- **именованный срез** — срез, имеющий имя и заданный условием на состояния либо местом в варианте. Местом заданы начальный и конечный; условием — заданные в проекте (в нынешнем проекте — «сдано бухгалтеру»). Именованный срез, условие которого не выполнено ни в одном срезе варианта, совпадает с конечным; он есть в каждом варианте;
- **пропуск** — ось проверки, оставшаяся на начальном значении;
- **ошибки без оси** — ошибки, у которых нет состояния или нет своей оси; ведутся отдельным списком без счёта.

Приложение делает четыре вещи:

1. Хранит проекты: справочник проекта, нормировку, пути двух сторон — «мы» и «они».
2. Принимает данные загрузкой файла проекта и вводом с экрана.
3. Проверяет данные: все названия есть в справочнике, каждый переход идёт из текущего значения, условия выполнены.
4. Считает по каждому варианту труд и пропуски проверок и показывает сравнение вариантов: таблицей и двумя графиками.

Версии:

1. Человек с языковой моделью разбирает процесс; модель готовит файл проекта; файл загружается; результат — сравнительная таблица. В окне всё видно, править нельзя.
2. Человек правит в окне уже загруженное.
3. Графическое сравнение путей: рост цены по длине, рост безопасности по длине.
4. Ручной ввод с пустого места.

Приложение не делает:

- не придумывает пути и не оценивает их за человека: числа берутся только из нормировки, которую ввёл пользователь;
- не ходит в сеть, не имеет учётных записей, сервера и совместной работы; обмен — файлами;
- не рисует схем; графиков два, оба в версии 2 (раздел 5.4);
- не работает с развилками: вариант всегда линейный, развилка записывается двумя вариантами.

Не включено, возможно позже (с причиной):

| Что | Почему не сейчас |
|---|---|
| Стоимость для пары «вид перехода + инструмент» (есть в нынешнем скрипте) | В принятой нормировке три множителя, инструмента среди них нет. Инструмент остаётся описательным параметром перехода |
| Прогон по размерам пачки 1, 10, 100, 1000 (есть в скрипте) | То же самое даёт другой коэффициент охвата в нормировке и пересчёт |
| Труд на участке до именованного среза | Отдельного столбца в таблице нет; труд, накопленный к каждому шагу, показывает график версии 2 |
| Сравнение двух вариантов по сдвинутым осям, поиск одинаковых срезов (есть в скрипте) | Для сравнения по труду и пропускам не нужны |
| Список запрещённых слов и проверка текста по нему (есть в скрипте) | Это правило оформления одного проекта, а не часть способа |
| Пометка у перехода «источник / гипотеза» | Сейчас пометки ведутся отдельным текстом. Нужна, только если пути конкурентов пойдут в публичный пример (вопрос process-11) |
| Группировка путей «они» по продуктам | Сейчас продукт виден из названия варианта, этого достаточно |
| История изменений, отмена на несколько действий назад | Проект сохраняется в файл; копия файла заменяет историю |

## 2. Модель данных

### 2.1. Где что лежит

- **Понятия способа** (сущность, ось, значение, срез, вид перехода, переход, вариант, параметр варианта, именованный срез, пропуск) в базе не хранятся строками. Они заданы устройством таблиц, кодом расчёта и описанием способа в репозитории. Они одинаковы для всех проектов.
- **Наполнение проекта** — строки таблиц: какие именно сущности, оси, значения, виды переходов, исполнители, параметры вариантов, какие числа, какие пути.
- **Результаты расчёта** в базе не хранятся: они пересчитываются при каждом показе. Так результат не может разойтись с данными.

### 2.2. Структура

```
проект
 ├─ перечень ошибок без оси (текст)
 ├─ справочник (формализм проекта) — один на проект
 │    ├─ сущности → оси → значения
 │    ├─ виды переходов → условия
 │    ├─ исполнители, инструменты, охваты
 │    ├─ параметры вариантов
 │    ├─ именованные срезы → условия
 │    └─ нормировка — одна на справочник
 │         ├─ стоимость вида перехода
 │         ├─ коэффициент исполнителя
 │         ├─ коэффициент охвата
 │         └─ цена пропуска по оси проверки
 └─ стороны: «мы», «они»
      └─ пути → переходы, значения параметров
```

Один справочник на проект: пути записаны в названиях справочника и без него не читаются. Другой справочник — это другой проект (проект копируется в списке проектов).

Нормировка одна на справочник. Другие числа — это правка нормировки и пересчёт; чтобы сохранить прежние числа, проект копируется.

### 2.3. Таблицы

У каждой таблицы есть `id`. «Порядок» — номер строки для показа. Ссылки идут по `id`, поэтому переименование в справочнике не ломает пути.

Проект и справочник:

| Таблица | Поля | Смысл |
|---|---|---|
| `project` | название, описание, перечень ошибок без оси | Проект; перечень — текст, в счёт не входит |
| `formalism` | проект (один к одному), имя оси наличия, значение «не существует» | Справочник проекта |
| `entity` | справочник, название, порядок | Сущность |
| `axis` | сущность, название, порядок | Ось состояния |
| `axis_value` | ось, название, порядок | Значение; первое по порядку — начальное |
| `axis_source` | ось, ось-источник, порядок | Откуда созданная сущность перенимает значение оси от другой сущности (место экземпляра, созданного из другого) |
| `kind` | справочник, название, порядок, значение «из», значение «в», признак «проверка», признак «вес 0», примечание к «вес 0» | Вид перехода; ось и сущность определяются значениями |
| `kind_condition` | вид перехода, значение | Строка условия: сущность, ось, значение (сущность и ось определяются значением). Все строки вида выполняются вместе; оси условия переходом не меняются |
| `executor` | справочник, название, порядок | Исполнитель |
| `instrument` | справочник, название, порядок | Инструмент |
| `scope` | справочник, название, порядок, признак «на пачку» | Охват |
| `variant_param` | справочник, название, порядок | Параметр варианта; его значение — исполнитель справочника |
| `named_slice` | справочник, название, порядок | Именованный срез, заданный условием. Начальный и конечный заданы местом в варианте, есть всегда и строками не хранятся |
| `named_slice_term` | именованный срез, номер группы, значение, параметр варианта, исполнитель | Строка условия среза: либо сущность, ось, значение (заполнено значение), либо параметр варианта и исполнитель. Внутри группы — все строки вместе («И»); между группами — «ИЛИ» |

Условие среза из групп нужно по факту: «сдано бухгалтеру» — это «экземпляр документа у бухгалтера **или** запись в учётной системе существует», а экземпляр «у получателя» считается у бухгалтера, только когда получатель — бухгалтер. Поэтому группа вида «Бумага: место = у получателя» **и** «получатель = бухгалтер».

Нормировка (одна на справочник, поэтому отдельной таблицы нормировки нет: строки ссылаются прямо на виды, исполнителей, охваты и оси):

| Таблица | Поля | Смысл |
|---|---|---|
| `norm_kind_cost` | вид перехода, стоимость | Строка на каждый вид без признака «вес 0»; у вида с «вес 0» строки нет, его стоимость 0 |
| `norm_executor` | исполнитель, коэффициент | Человек 1, программа или служба 0 |
| `norm_scope` | охват, коэффициент | Число на каждый охват справочника; задаёт пользователь |
| `norm_skip_price` | ось проверки, цена пропуска | 1 или 3 |

Стороны и пути:

| Таблица | Поля | Смысл |
|---|---|---|
| `side` | проект, роль («мы» или «они»), подпись | Ровно две строки на проект, создаются вместе с проектом |
| `path` | сторона, код, название, порядок, причина «вне сравнения» (пусто — вариант сравнивается) | Вариант пути; код не повторяется в проекте |
| `path_entity` | путь, сущность | Состав сущностей варианта; если строк нет — сущности, которых касаются переходы варианта |
| `path_initial` | путь, значение | Отклонение начального среза от начальных значений |
| `path_param` | путь, параметр варианта, исполнитель | Кто занимает роль в этом варианте; задаётся для каждого параметра |
| `path_step` | путь, порядок, вид перехода, исполнитель, инструмент, охват | Переход в варианте |

Таблиц 24.

Числа (стоимость, коэффициент, цена) хранятся десятичной записью, не числом с плавающей точкой.

Чего в таблицах сознательно нет:

- признака «ось проверки» у оси: ось проверки — ось, которую меняет вид с признаком «проверка»;
- признака «человек» у исполнителя: человек — тот, у кого коэффициент больше нуля;
- отдельной таблицы нормировки: нормировка одна на справочник.

## 3. Загрузка файлами

### 3.1. Что грузится

Один файл проекта, JSON. В нём всё: название и описание проекта; справочник (ось наличия, сущности с осями и значениями, виды переходов с условиями и признаками «проверка» и «вес 0», исполнители, инструменты, охваты, охват «на пачку», параметры вариантов, именованные срезы с условиями); варианты (код, название, сторона, переходы, состав сущностей, отклонения начального среза, значения параметров, причина «вне сравнения»); нормировка (стоимости видов переходов, коэффициенты исполнителей и охватов, цены пропусков, перечень ошибок без оси, размер пачки — справочное число, в расчёт не входит).

Файл готовит языковая модель в разговоре с человеком, по описанию формата. Человек файл не читает и не правит: загружает его и всё видит в окне. Загрузка создаёт новый проект или заменяет выбранный («загрузить поверх»). Тем же файлом проект выгружается.

Названия в файле — словами, не номерами. Строка условия — тройка «сущность, ось, значение»; у среза строка может быть и парой «параметр варианта, исполнитель».

Отдельных файлов справочника, нормировки и путей нет.

### 3.2. Соотношение с файлами нынешнего скрипта

Скрипт читает два файла: модель (справочник и варианты) и нормировку. Названия полей в файле проекта — те же, что у скрипта. Отличия:

| У скрипта | В файле проекта |
|---|---|
| Модель и нормировка — два файла | Один файл; нормировка — его раздел |
| Номера формата и названия проекта нет | Есть оба |
| Стороны нет | Сторона — поле варианта: свой или чужой; без поля — свой |
| Числа прежнего расчёта у вида перехода и у исполнителя | Не используются; числа только в нормировке |
| Тексты оформления и запрещённые слова | Не используются |
| Срез, который в варианте не наступил, считается по конечному только по отдельному полю нормировки | Считается по конечному всегда; поля нет |
| Стоимость вида с признаком «вес 0» обязана быть записана нулём | Можно не писать; если записана — только 0 |
| Цена пропуска записана по названию оси | По паре «сущность, ось»; одинаковые названия осей проверки у разных сущностей разрешены |

Файлы прежнего вида (модель и отдельная нормировка) приложение не принимает.

### 3.3. Проверки при загрузке

Файл загружается целиком или не загружается вовсе. При отказе показывается полный список ошибок, а не первая. Каждая ошибка называет место: вид перехода, или вариант и номер перехода. Замечания — на английском, как окно; названия из справочника — как введены.

Справочник:

- названия не повторяются: сущности; оси в сущности; значения в оси; виды переходов; исполнители; инструменты; охваты; параметры вариантов; именованные срезы;
- у оси есть хотя бы одно значение;
- вид перехода ссылается на существующие сущность, ось и оба значения; «из» не равно «в»;
- строка условия вида перехода ссылается на существующие сущность, ось и значение и не на собственную ось вида;
- признак «на пачку» стоит не больше чем у одного охвата;
- источник начального значения существует;
- у оси наличия есть значение «не существует»;
- нет двух видов с одинаковой четвёркой «сущность, ось, из, в»;
- ни один вид не повторяется цепочкой из других видов по той же оси (иначе один и тот же сдвиг можно записать двумя способами);
- строка условия именованного среза ссылается на существующие сущность, ось и значение либо на существующие параметр варианта и исполнителя.

Нормировка:

- все названия есть в справочнике проекта;
- стоимость — число не меньше нуля; коэффициент исполнителя и коэффициент охвата — числа не меньше нуля; цена пропуска — число больше нуля;
- у вида с признаком «вес 0» стоимость не задана либо равна 0;
- цена задана только для осей проверки.

В версии 1 неполная нормировка не загружается: отказ с замечанием о каждом недостающем числе. С версии 3 числа правятся в окне; варианты, которым не хватает чисел, получают в сравнении «не задано» вместо результата, недостающее показывается списком.

Пути:

- код варианта не повторяется в проекте;
- вид перехода, исполнитель, инструмент, охват, сущности состава, значения отклонений и параметры варианта есть в справочнике;
- у варианта задано значение каждого параметра варианта, и это исполнитель справочника;
- причина «вне сравнения», если указана, — непустой текст;
- прогон: сущность перехода входит в состав варианта; текущее значение оси равно «из» вида перехода; условие вида выполнено в текущем срезе. Сообщение: вариант, номер перехода, вид, что ожидалось и что есть.

С версии 3 (правка в окне): если справочник заменён или изменён, когда пути уже есть, все пути прогоняются заново; путь с ошибкой остаётся в базе с пометкой «с ошибкой» и в сравнение не идёт. Удаление из справочника того, что используется в путях или нормировке, отклоняется со списком мест.

## 4. Экран

Окно одно. Сверху — выбор проекта, ниже три вкладки в порядке работы: Справочник; Нормировка и варианты; Сравнение. Разделы 4.3 и 4.4 — две половины второй вкладки. В версии 1 вкладки только для просмотра; правка — с версии 3; ввод с пустого места — версия 4. Подписи в окне — на английском. Четвёртая вкладка `Step chains` — раздел 4.6.

### 4.1. Проекты

Список проектов. Действия: загрузить из файла проекта, загрузить поверх выбранного, выгрузить в файл, скопировать, удалить (с подтверждением); создать пустой — с версии 4. При отказе в загрузке — полный список замечаний с кнопкой «скопировать»: человек передаёт его языковой модели.

### 4.2. Справочник

- Слева дерево: сущность → оси → значения. Порядок меняется перетаскиванием; первое значение — начальное. У оси созданной сущности — источники начального значения.
- Справа списки: виды переходов (название, сущность, ось, из, в, условие — строки «сущность, ось, значение», всё выбором из списков, не набором текста; галочки «проверка» и «вес 0», примечание к «вес 0»), исполнители, инструменты, охваты (галочка «на пачку»), параметры вариантов, именованные срезы (название и условие: группы строк «сущность, ось, значение» или «параметр варианта, исполнитель»; между группами «ИЛИ»).
- Внизу — список ошибок справочника и счёт: сущностей, осей, значений, видов переходов; виды переходов и исполнители, не использованные ни в одном пути.

### 4.3. Нормировка

- Четыре таблицы, строки которых берутся из справочника, вводятся только числа:
  - виды переходов: стоимость; вид с признаком «вес 0» показан со стоимостью 0 без ввода;
  - исполнители: коэффициент;
  - охваты: коэффициент;
  - оси проверки: цена пропуска.
- Незаполненные ячейки выделены; число незаполненных показано.
- Число правится в ячейке (запятая или точка, показ с точкой; пустое — `not set`), принимается по Enter или уходу из ячейки и сразу пишется в базу; все вкладки пересчитываются, выбор, сторона, сортировка и раскрытые строки остаются. Над таблицами серым `Changes are saved at once. To keep the old numbers, copy the project.`, янтарём `N numbers not set`; отказ — ячейка прежняя, под таблицей красная строка причины.

### 4.4. Пути

- Слева список вариантов в двух группах — «мы» и «они»; у варианта с ошибкой пометка. Действия: новый, копия (варианты часто отличаются несколькими переходами), удалить.
- Справа выбранный вариант:
  - код, название, сторона, галочка «вне сравнения» с причиной;
  - значения параметров варианта (выбор исполнителя для каждого параметра);
  - состав сущностей (галочки; по умолчанию — сущности, которых касаются переходы) и отклонения начального среза;
  - таблица переходов: номер, вид, исполнитель, инструмент, охват, и что изменилось («ось: из → в»);
  - под таблицей — срез после выбранной строки: сущности и значения осей, изменившееся значение выделено.

Ввод варианта с экрана:

1. Заполняются код, название, сторона, значения параметров варианта. Показывается начальный срез.
2. Кнопка «Добавить переход». В списке видов переходов показаны только те, что разрешены из текущего среза: текущее значение оси равно «из», условие выполнено. Остальные виды видны отдельно серым, с причиной, почему не разрешены.
3. Выбираются вид, исполнитель, инструмент, охват. Исполнитель, инструмент и охват по умолчанию — как в предыдущей строке.
4. Строка добавляется, срез пересчитывается и показывается.
5. Строку можно вставить в середину, удалить, передвинуть. После этого вариант прогоняется заново; первая строка, которая перестала проходить, выделяется с сообщением. Вариант с ошибкой можно сохранить и доделать позже; в сравнение он не идёт.

### 4.5. Сравнение

Одна таблица, сгруппированная по задаче (`task` варианта). Строка группы — заголовок на всю ширину; справа серым `N variants`. Группы по порядку:

1. Группы с парой — заголовок `Task: <задача>`; в группе два и более сравниваемых варианта, любой стороны. Порядок — по алфавиту задачи.
2. `No comparable variant` — задача у варианта одна или её нет. Заголовок серый, под ним серым `Not compared: no other variant has the same task`.
3. `Out of comparison` — варианты с `out_of_comparison`, независимо от задачи. Заголовок серый; такой вариант пару не составляет.

Строка — вариант:

| Столбец | Содержание |
|---|---|
| `Code` | код; слева значок раскрытия шагов |
| `Title` | название; у строки «вне сравнения» второй серой строкой `Reason: …` |
| `Side` | `● Ours` или `○ Theirs` |
| `Steps` | число переходов варианта |
| `Labour · <исполнитель>` | по одному столбцу на исполнителя с коэффициентом больше нуля, в единицах стоимости |
| `Labour · total` | сумма столбцов труда |
| `Skipped checks, <срез>` | по одному на каждый именованный срез: сумма цен пропусков |
| `Skipped checks, end` | то же на конечном срезе |

- Внутри группы свои стоят над чужими: свой вариант — точка отсчёта. По умолчанию — по `Labour · total`, от меньшего, при равенстве по коду. У своих слева полоса цветом акцента.
- Клик по заголовку столбца сортирует строки внутри каждой группы, по числам. Порядок групп не меняется, свои остаются над чужими.
- Фильтр `All` / `Ours` / `Theirs` скрывает строки другой стороны; группа без видимых строк скрывается. Группа не распадается: состав групп считается по всем вариантам, `N variants` показывает его полностью.
- В группе с парой наименьший `Labour · total` среди видимых строк выделен жирным; при равенстве — все равные. В остальных группах жирного нет.
- Варианты «вне сравнения» считаются так же, как остальные, и показываются с числами. С версии 3 туда же — варианты с ошибкой и варианты, которым не хватает чисел нормировки.
- Число, которое не посчитать из-за незаданного числа нормировки, — `not set` (на экране, в шагах и в выгрузке); причина `Not set: cost of <вид>, …`. У варианта с ошибкой прогона чисел нет — `—`, причина `Error at transition N: …`, в шагах все переходы. На графиках и шкале труда такие варианты не рисуются.
- Ниже таблицы — подсказка и перечень ошибок без оси, текстом, как введён; правится здесь же. В итог не входит.

Шаги варианта:
- Клик по строке открывает шаги под ней, повторный клик закрывает; открытыми могут быть несколько вариантов.
- Таблица шагов: `#`, `Kind`, `Executor`, `Instrument`, `Scope`, `Cost`, `Scope ×`, `Executor ×`, `Labour` (стоимость × коэффициент охвата × коэффициент исполнителя), `Skips left` — число пропусков на срезе после этого шага, `Changes` — смены значений осей.
- Под шагами — строки `Skipped checks, <срез>: …` и `Skipped checks, end: …` со списком пропущенных осей и цен. Срез, который не наступил, помечен `(not reached)`.

Вид `Compare steps`:
- Кнопка в заголовке группы с парой; у `No comparable variant` и `Out of comparison` её нет.
- Вид открывается на месте таблицы; `Back to table` возвращает таблицу с прежними раскрытыми строками, сортировкой и фильтром.
- Столбцы — варианты группы в порядке таблицы, с учётом фильтра. Строки — номера шагов от 1 до длины самого длинного варианта; у короткого нижние ячейки пустые.
- В ячейке: вид перехода, накопленный труд после шага, `Skips left: N`. Если на шаге наступает именованный срез, в ячейке его метка. Последняя ячейка варианта — жирная, в ней итог, равный строке таблицы.
- Вид только для просмотра.

- В версии 2 в виде `Compare steps` под столбцами шагов — шкала труда, под ней два графика (раздел 5.4); линии графиков — те же варианты, что столбцы вида: одна задача, с учётом отбора по стороне. Линии разных задач на одном графике не бывают. Под таблицей графиков нет.
- Кнопки «Выгрузить» (Export Markdown, Export CSV): те же группы, перечень ошибок без оси и подробности шагов.
  - Markdown: на каждую группу заголовок (`## Task: …`, `## No comparable variant`, `## Out of comparison`) и своя таблица с теми же столбцами; в группе «вне сравнения» добавлен столбец `Reason`. Дальше — перечень ошибок без оси и раздел `Details` по шагам каждого варианта.
  - CSV: одна таблица, первым столбцом `Group`, последним `Reason` (пустой у сравниваемых); строки — в порядке экрана по умолчанию.

### 4.6. Цепочки шагов

Четвёртая вкладка `Step chains`, после `Comparison`; правятся только переходы. Показывает путь как цепочку шагов человека (поле `steps`, `docs/input_format_ru.md`) с их переходами. Подробности и решения — `docs/decomposition_view_ru.md`.

Слева список путей:
- Группы и порядок — как в сравнении (4.5): `Task: <задача>`, `No comparable variant`, `Out of comparison`; внутри группы свои над чужими. Фильтра и сортировки нет.
- Строка пути: код и название; ниже серым сторона (`● Ours` / `○ Theirs`) и `N transitions`; если есть шаги без переходов — ещё строка `N steps without transitions` (`1 step without transitions`). У своих слева полоса цветом акцента. Серым — только пути `Out of comparison`.
- Выбран первый путь списка.

Справа цепочка выбранного пути:
- Шапка: код и название; справа серым сторона, `Task: <задача>` (у пути без задачи слова нет), число шагов и переходов.
- Таблица: строка шага человека — номер и текст, жирным, на всю ширину; под ней его переходы: `#` (сквозной, как в `calls`), `Kind`, `Executor`, `Instrument`, `Scope`. Шаг без переходов — серым `No transitions`. Метка именованного среза — пунктирная строка `slice “<имя>” reached` после перехода, на котором срез наступил; значений осей нет.
- Путь без `steps` (файл, подготовленный раньше) — те же переходы одним списком; в шапке вместо числа шагов серым `Steps not given`; в счёт пустых шагов он не идёт.
- Справа от `Scope` у каждого перехода кнопки `↑ ↓ ✕ +` (подсказки `Move up`, `Move down`, `Remove`, `Add transition below`); `↑` у первого перехода пути и `↓` у последнего выключены; через границу шага переход уходит в соседний шаг. У пустого шага — только `+`. `+` открывает под строкой строку ввода: `Kind` (все виды справочника), `Executor`, `Instrument`, `Scope` — по умолчанию как в строке выше (у пустого шага — ближайший переход выше, иначе ниже), и `Add` / `Cancel`. Правка сразу пишется в базу, все вкладки пересчитываются, выбранный путь остаётся; отказ — красная строка причины под цепочкой.
- У пути с ошибкой прогона переход N — красным жирным, под ним красная строка `Error at transition N: …`.

Предложение после загрузки:
- После `Load` и `Load over` без замечаний окно остаётся на `Comparison`. Под строкой вкладок — полоса на всю ширину: `<проект> loaded: N paths.` (`1 path` / `5 paths`) `Check how your steps were split into transitions before you compare.` и, если K больше нуля, `K steps have no transitions.` (`1 step has`). `N` — все пути проекта, `K` — шаги без переходов во всех путях.
- Кнопки: `Show step chains` — открывает вкладку на первом пути с пустыми шагами (если таких нет — на первом пути) и скрывает полосу; `Not now` — скрывает только полосу.
- На вкладке `Step chains` стоит точка (значок перед подписью, подпись не меняется), пока вкладку не открыли после этой загрузки; `Not now` её не убирает. Если вкладка уже открыта при загрузке, точки нет.
- При выборе проекта из списка без загрузки файла, и при загрузке с замечаниями, полосы и точки нет.

## 5. Счёт

Обозначения: у варианта переходы 1…n; срез 0 — начальный, срез i — после перехода i, срез n — конечный.

### 5.1. Срезы

- Начальный срез: каждая ось сущности варианта получает первое значение; отклонения варианта заменяют его указанными значениями. У несуществующей сущности значение имеет только ось наличия.
- Вид перехода меняет значение одной оси одной сущности: было «из», стало «в». Больше ничего при переходе не меняется. У вида может быть условие: переход возможен, только если названные в условии оси уже имеют названные значения. Сами эти оси остаются как были.
- При создании сущности (ось наличия уходит со значения «не существует») остальные её оси, у которых до того значений не было, получают начальные значения: перенимают значение от другой сущности — от первого источника, у которого значение есть, иначе первое значение оси. Это начальные значения, а не изменение значений.
- При уничтожении сущности остальные её оси теряют значения.

### 5.2. Труд

- Труд перехода = стоимость вида перехода × коэффициент охвата × коэффициент исполнителя. Коэффициент охвата — число из нормировки для охвата этого перехода; приложение только перемножает. Единицу стоимости выбирает пользователь, она одна на проект; приложение единицы не знает.
- У вида с признаком «вес 0» стоимость 0.
- Пример: вид стоимостью 2, охват с коэффициентом 0,01, исполнитель с коэффициентом 1: 2 × 0,01 × 1 = 0,02.
- Итог пути — отдельно по каждому исполнителю с коэффициентом больше нуля (сумма труда его переходов) и вместе (сумма по всем переходам варианта).
- Столбец в сравнении получает каждый исполнитель с коэффициентом больше нуля, у которого есть хотя бы один переход в вариантах проекта.
- Счёт ведётся точными дробями; печатается с двумя знаками после запятой, в подробностях — без округления.
- С версии 3: если переходу не хватает числа (стоимости, коэффициента исполнителя или коэффициента охвата), труд варианта не считается: печатается «не задано» и перечень недостающего.

### 5.3. Пропуски

- Именованный срез, заданный условием, в варианте — первый по порядку срез, в котором выполнено его условие (все строки хотя бы одной группы; строка «параметр варианта, исполнитель» выполнена, если в варианте этот параметр занимает этот исполнитель). Если такого среза нет, именованный срез совпадает с конечным. Он есть в каждом варианте, пропуски на нём считаются всегда.
- Пропуск на срезе — ось проверки, значение которой в этом срезе равно начальному значению оси.
- Итог на срезе = сумма цен пропусков; рядом список пропусков.
- Считается на каждом именованном срезе проекта, заданном условием, и на конечном срезе. Исполнитель и охват в этот счёт не входят. В версии 2 пропуски считаются на каждом срезе варианта — для графика.
- С версии 3: если у оси проверки нет цены, итог — «не задано» с перечнем таких осей; список пропусков печатается всё равно.
- Ошибки без оси в счёт не входят: их перечень показывается в сравнении отдельно.

### 5.4. Графики (версия 2)

Два графика, по линии на вариант; по горизонтали — номер шага.

- **Цена по длине** — труд, накопленный после каждого шага.
- **Безопасность по длине** — сумма цен сделанных проверок на срезе после шага. Проверка сделана, если у оси проверки есть значение и оно не начальное; считаются все оси проверки справочника. Линия растёт, а опускается только там, где проверка откатилась на начальное значение. Вариант без проверок лежит на нуле.

Пути разной длины: по горизонтали номер шага, линия кончается на последнем шаге своего пути.

Как построено:

- Два графика один под другим: `Labour by step` и `Checks done by step`, в виде `Compare steps` группы задачи под шкалой труда; линии — столбцы вида (одна задача, отбор по стороне учтён). Под таблицей сравнения графиков нет: линии разных задач на одном графике не сравнивают. Рисуются средствами QtCharts (модуль входит в PySide6). По горизонтали целые номера шагов; линия начинается в точке 0 — начальный срез (труд 0), — и кончается на последнем шаге своего пути.
- Линия на вариант, подпись в легенде — код варианта. Цвет линии стабилен: берётся из ряда `style.SERIES` по номеру варианта в проекте, поэтому при смене отбора цвет варианта не меняется. Свои варианты — сплошной линией, чужие — пунктиром.
- Шкала труда — виджет на `QPainter` в виде `Compare steps`, под столбцами шагов, строки — варианты в порядке таблицы с учётом отбора. Общая ось труда от 0 до наибольшего итога. На строку: полоса отрезков по шагам (длина — труд шага, цвет — исполнитель, нулевой шаг — черта), `✓` над концом шага, на котором выросла сумма цен сделанных проверок, пунктир с именем в конце шага, где наступил именованный срез, полоска состояния (зелёная — пропусков нет, розовая — есть), справа итог труда и число пропусков в конце. Виджет сначала строит список того, что рисует, и рисует по нему.

### 5.5. Что печатается

Сравнение (раздел 4.5) на экране и в выгрузке; графики версии 2; подробности варианта; перечень ошибок без оси; при загрузке — список ошибок. Больше ничего.

| Язык | Python 3.14 | На нём написан нынешний скрипт: проверка модели и прогон срезов переносятся без переписывания; язык автора | JavaScript, приложение одной страницей в браузере: установки нет вовсе, но расчёт пишется заново, а база и окна — другими средствами |
| Графика | PySide6, обычные окна Qt (без встроенного браузера) | Автор работает с PySide6; одинаково на Linux и Windows; без встроенного браузера сборка заметно меньше | Страница в браузере, отдаваемая программой с этого же компьютера: меньше сборка, но посторонний человек запускает «сервер» и открывает адрес — это сложнее объяснить |
| База | SQLite, один файл в папке данных пользователя | Входит в Python, ставить и настраивать нечего; база переносится копированием файла | MariaDB: у автора есть, но постороннему пришлось бы ставить сервер и заводить пользователя — для бесплатной раздачи не годится |
| Доступ к базе | Модуль `sqlite3` из Python, запросы написаны явно, номер версии структуры в базе | 24 таблицы; без зависимостей, сборка меньше | Django как ORM (привычен автору, готовые миграции): лишняя крупная зависимость и настройка ради 24 таблиц |
| Раздача | Готовая сборка для Windows и Linux на странице выпусков GitHub (PyInstaller); тем, у кого есть Python, — установка одной командой | Постороннему: скачать, распаковать, запустить | Только установка через Python: проще автору, но бухгалтеру без Python недоступно |

Зависимость одна — PySide6. Ядро (модель, проверки, счёт) остаётся на чистом Python без Qt и без базы и проверяется отдельно.

Графики версии 2 используют модуль QtCharts: в сборку и в установку берётся PySide6 целиком (с Addons), а не только PySide6-Essentials; в `pyproject.toml` PySide6 пока не записан.

Не проверено, проверяется при постройке (часть 4): что PySide6 и PyInstaller собирают рабочую программу на Python 3.14 под Windows; размер сборки. Известный факт: неподписанная программа при первом запуске в Windows вызывает предупреждение SmartScreen; подпись стоит денег.

## 7. Что берётся из нынешнего скрипта

Скрипт: 7 модулей, около 1450 строк, чистый Python; тесты на нейтральном примере. Принимает один JSON-файл модели; проверяет справочники и варианты, прогоняет срезы, считает справочники, стоимость пути и число переходов-проверок, участки до цели; печатает текст и Markdown.

| Часть скрипта | Судьба |
|---|---|
| Прогон варианта: начальный срез, применение перехода, перенимание значения от другой сущности при создании, проверка «из» и условия | Берётся целиком |
| Описание модели и проверка названий | Берётся; ошибки собираются списком, а не до первой |
| Проверка разделения: одинаковые четвёрки, повтор цепочкой | Берётся целиком |
| Счёт справочников, неиспользованные виды и исполнители | Берётся целиком |
| Стоимость пути | Правило меняется: отдельно по исполнителям, коэффициент охвата из нормировки вместо общего размера пачки, без стоимости по инструменту, точные дроби |
| Поиск первого среза, где цель достигнута | Берётся для именованных срезов; добавляются группы через «ИЛИ», строки с параметром варианта и совпадение с конечным, если условие не выполнено |
| Печать среза строкой с выделением изменившегося | Берётся для выгрузки подробностей |
| Тесты | Берутся за основу; нейтральный пример из тестов расширяется |
| Безопасность как число переходов-проверок | Не берётся: в таблице — пропуски на срезе, на графике версии 2 — сумма цен сделанных проверок |
| Прогон по размерам пачки; одинаковые срезы; сравнение сдвинутых осей с опорным вариантом; запрещённые слова; полная печать модели с разделами | Не берутся (раздел 1). Остаются в истории репозитория |
| Командная строка | Остаются две команды: проверить файлы и напечатать сравнение — тот же счёт, что на экране, без окна |

Состояние репозитория скрипта: один коммит; после него есть незакоммиченные правки в семи файлах и новый модуль участков до цели. Перед постройкой это состояние надо зафиксировать.

## 8. Публичный репозиторий

### 8.1. Состав

- Описание способа: понятия, как записывается путь, что даёт сравнение (труд по людям, пропуски проверок), где способ не применим (развилки, параллельные действия). Без привязки к счетам, на маленьком нейтральном примере.
- Руководство: установка, вкладки, ввод пути с экрана, формат файла, правила счёта.
- Пример: файл проекта, который открывается сразу после установки.
- Программа, тесты, лицензия GPL v3 (GPL-3.0-or-later); автор — Ilia Tsigelnitskii.

### 8.2. Нынешний проект как пример: факты

Что есть и что в нём видно:

| Материал | Что раскрывает |
|---|---|
| Справочник обработки счетов (9 сущностей, 28 осей, 31 вид перехода) | Общий порядок обработки документа; исполнитель «наша программа»; определения ссылаются на пути А, Б, В, Г |
| 11 наших вариантов | Как устроена работа нашей программы по замыслу; файл помечен «слой: замысел», то есть это не описание выпущенного продукта |
| 32 варианта конкурентов | Названия пяти продуктов (Dext, AutoEntry, Hubdoc, Datamolino, QuickBooks Online) и вариант «Человек с LLM»; по каждому — последовательность действий и, после расчёта, оценки труда и пропусков |
| Нормировка | Наши оценки стоимости действий и цен пропусков |

Риски публикации вариантов конкурентов:

1. Из 491 перехода в вариантах конкурентов 218 опираются на источник, 26 — только на сводку поиска, 247 — гипотезы автора модели. Доля гипотез по вариантам — от 33 до 67 %.
2. Пометки «источник / гипотеза» лежат в отдельном тексте, в самих вариантах их нет: опубликованный файл путей выглядел бы как утверждение о чужом продукте без оговорок.
3. Сведения собраны из сети 15.11.2026; продукты меняются, пример устареет.
4. Есть неснятые расхождения: в шести вариантах (AE3, AE4, HD3, HD4, QB3, QB4) нет «принятия»; «подтверждение» службой в трёх вариантах помечено к перепроверке; пути не переведены на новый справочник.
5. Сравнение, в котором автор программы оценивает названные чужие продукты и выигрывает, читается как реклама и может вызвать претензии правообладателей названий.
6. Замена названий на «Продукт 1…5» убирает названия, но набор действий остаётся узнаваемым для знающего рынок.

Что придётся убрать при любом решении: ссылки на внутренние файлы и номера решений в текстах, список запрещённых слов, заметки о конкурентах с выдержками, записи опытов нормировки, журнал решений. Пример готовится отдельным файлом проекта, а не выгрузкой рабочих файлов как есть.

Возможные решения (выбирает заказчик, вопрос process-11):

- а) примера со счетами нет, только нейтральный;
- б) наши варианты и обезличенные варианты конкурентов;
- в) наши варианты и варианты конкурентов с названиями, с пометкой у каждого перехода «источник / гипотеза» и датой сбора;
- г) только наши варианты и «ручной ввод», без конкурентов.

Отдельно: история репозитория станет публичной вместе с именем и почтой автора коммитов. Нынешний единственный коммит перед публикацией надо просмотреть.

## 10. Решено без вопроса

- У вида с признаком «вес 0» стоимость 0; в нормировку её можно не вносить, а если внесена — только 0.
- Значение каждого параметра варианта у варианта обязательно.
- При создании сущности остальные её оси получают начальные значения; это не изменение значений, у несуществующей сущности их не было.
- Результаты расчёта в базе не хранятся.
- Стороны ровно две; продукт конкурента остаётся в названии варианта.
- Файл загружается целиком или не загружается; ошибки — полным списком.

## 11. Вопросы заказчику

Решены:

- **process-6.** Справочник в проекте один; попробовать другой справочник — значит скопировать проект. Решение: один справочник на проект.
- **process-7.** Решение: нормировка одна на справочник.
- **process-8.** Раздел чисел и справочника. Решение: в справочнике — признаки «проверка» и «вес 0» (с примечанием) у вида перехода, признак «на пачку» у охвата; в нормировке — стоимость вида перехода, коэффициент исполнителя, коэффициент охвата, цена пропуска по оси проверки.
- **process-9.** Решение: труда на документ нет. Труд перехода = стоимость вида × коэффициент охвата × коэффициент исполнителя, в нажатиях; итог пути — по каждому исполнителю с коэффициентом больше нуля и вместе.
- **process-10.** Решение: Python, окна PySide6, база SQLite одним файлом, готовые сборки для Windows и Linux.
- **process-12.** Решение: окно — на английском; описание — на английском и на русском.
- **process-13.** Решение: лицензия GPL v3 (GPL-3.0-or-later); автор — Ilia Tsigelnitskii.
- **process-15.** Решение: проекты хранятся в базе SQLite; файл — для загрузки, выгрузки и пересылки.
- **process-16.** Решение: четыре версии, как в разделе 1.
- **process-18.** Решение: «безопасность» числом — сумма цен проверок, сделанных к данному месту пути; линия растёт.
- **process-19.** Версия 1 отказывает в загрузке с замечанием, если в нормировке не хватает числа; «не задано» у варианта — с версии 3.
- **process-20.** На графике по горизонтали номер шага; линия кончается на последнем шаге своего пути.
- **process-21.** Проверка сделана, если у оси проверки есть значение и оно не начальное; считаются все оси проверки справочника; вернувшаяся на начальное значение перестаёт считаться. Линия безопасности растёт, а опускается только там, где проверка откатилась.
- **process-22.** Замечания — на английском, как окно; названия из справочника — как введены.
- **process-23.** Цена пропуска записывается по паре «сущность, ось»; одинаковые названия осей проверки у разных сущностей разрешены.
- **process-24.** Текста определений проекта и примечания к стоимости нет ни в файле, ни в окне.
- **process-25.** Если список сущностей варианта не задан, берутся сущности, которых касаются переходы варианта.
