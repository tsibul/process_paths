# Проект приложения «Сравнение путей»

Документ — проект, без кода. Наполнение (справочник, нормировка, пути) вносится позже, когда закончатся работы над ними.

## 1. Назначение и границы

Способ, который приложение обслуживает:

- **сущность** — то, у чего есть состояние; у сущности есть **оси состояния**, у оси — перечень **значений**, первое — начальное;
- **срез** — значения всех осей всех сущностей варианта в один момент;
- **вид перехода** — вид перехода меняет значение одной оси одной сущности: было «из», стало «в». Больше ничего при переходе не меняется. У вида может быть условие: переход возможен, только если названные в условии оси уже имеют названные значения. Сами эти оси остаются как были;
- **проверка** — признак вида перехода; **ось проверки** — ось, которую меняет вид с этим признаком;
- **вес 0** — признак вида перехода с примечанием: переход остаётся в пути, его стоимость труда 0;
- **переход в варианте** — четвёрка: вид перехода, исполнитель, инструмент, охват; какой охват считается «на пачку», задаёт справочник;
- **параметр варианта** — названная роль, которую в каждом варианте занимает один из исполнителей справочника; кто именно, задаёт вариант (в нынешнем проекте — «получатель»);
- **вариант пути** — линейная последовательность переходов, без развилок; вариант может задать список своих сущностей, если список не задан, участвуют все сущности справочника;
- **именованный срез** — срез, имеющий имя и заданный условием на состояния либо местом в варианте. Местом заданы начальный и конечный; условием — заданные в проекте (в нынешнем проекте — «сдано бухгалтеру»). Именованный срез, условие которого не выполнено ни в одном срезе варианта, совпадает с конечным; он есть в каждом варианте;
- **пропуск** — ось проверки, оставшаяся на начальном значении;
- **ошибки без оси** — ошибки, у которых нет состояния или нет своей оси; ведутся отдельным списком без счёта.

Приложение делает четыре вещи:

1. Хранит проекты: справочник проекта, нормировку, пути двух сторон — «мы» и «они».
2. Принимает данные двумя способами: загрузкой файлов и вводом с экрана.
3. Проверяет данные: все названия есть в справочнике, каждый переход идёт из текущего значения, условия выполнены.
4. Считает по каждому варианту труд и пропуски проверок и показывает сравнение вариантов.

Приложение не делает:

- не придумывает пути и не оценивает их за человека: числа берутся только из нормировки, которую ввёл пользователь;
- не ходит в сеть, не имеет учётных записей, сервера и совместной работы; обмен — файлами;
- не рисует схем и графиков;
- не работает с развилками: вариант всегда линейный, развилка записывается двумя вариантами.

Не включено, возможно позже (с причиной):

| Что | Почему не сейчас |
|---|---|
| Стоимость для пары «вид перехода + инструмент» (есть в нынешнем скрипте) | В принятой нормировке три множителя, инструмента среди них нет. Инструмент остаётся описательным параметром перехода |
| Прогон по размерам пачки 1, 10, 100, 1000 (есть в скрипте) | То же самое даёт другой коэффициент охвата в нормировке и пересчёт |
| Труд на участке до именованного среза | Заказано: труд за весь путь, пропуски на двух срезах. Добавляется без переделки, если понадобится |
| Сравнение двух вариантов по сдвинутым осям, поиск одинаковых срезов (есть в скрипте) | Для сравнения по труду и пропускам не нужны |
| Список запрещённых слов и проверка текста по нему (есть в скрипте) | Это правило оформления одного проекта, а не часть способа |
| Пометка у перехода «источник / гипотеза» | Сейчас пометки ведутся отдельным текстом. Нужна, только если пути конкурентов пойдут в публичный пример (вопрос process-11) |
| Группировка путей «они» по продуктам | Сейчас продукт виден из названия варианта, этого достаточно |
| История изменений, отмена на несколько действий назад | Проект сохраняется в файл; копия файла заменяет историю |

## 2. Модель данных

### 2.1. Где что лежит

- **Понятия способа** (сущность, ось, значение, срез, вид перехода, переход, вариант, параметр варианта, именованный срез, пропуск) в базе не хранятся строками. Они заданы устройством таблиц, кодом расчёта и описанием способа в репозитории. Они одинаковы для всех проектов.
- **Наполнение проекта** — строки таблиц: какие именно сущности, оси, значения, виды переходов, исполнители, параметры вариантов, какие числа, какие пути. Определения, свои для проекта (например, «экземпляр», «принятие»), хранятся текстом в справочнике проекта.
- **Результаты расчёта** в базе не хранятся: они пересчитываются при каждом показе. Так результат не может разойтись с данными.

### 2.2. Структура

```
проект
 ├─ перечень ошибок без оси (текст)
 ├─ справочник (формализм проекта) — один на проект
 │    ├─ сущности → оси → значения
 │    ├─ виды переходов → условия
 │    ├─ исполнители, инструменты, охваты
 │    ├─ параметры вариантов
 │    ├─ именованные срезы → условия
 │    └─ нормировка — одна на справочник
 │         ├─ стоимость вида перехода
 │         ├─ коэффициент исполнителя
 │         ├─ коэффициент охвата
 │         └─ цена пропуска по оси проверки
 └─ стороны: «мы», «они»
      └─ пути → переходы, значения параметров
```

Один справочник на проект: пути записаны в названиях справочника и без него не читаются. Другой справочник — это другой проект (проект копируется выгрузкой и загрузкой файла).

Нормировка одна на справочник. Другие числа — это правка нормировки и пересчёт; чтобы сохранить прежние числа, нормировка выгружается в файл.

### 2.3. Таблицы

У каждой таблицы есть `id`. «Порядок» — номер строки для показа. Ссылки идут по `id`, поэтому переименование в справочнике не ломает пути.

Проект и справочник:

| Таблица | Поля | Смысл |
|---|---|---|
| `project` | название, описание, перечень ошибок без оси | Проект; перечень — текст, в счёт не входит |
| `formalism` | проект (один к одному), текст определений, имя оси наличия, значение «не существует» | Справочник проекта |
| `entity` | справочник, название, порядок | Сущность |
| `axis` | сущность, название, порядок | Ось состояния |
| `axis_value` | ось, название, порядок | Значение; первое по порядку — начальное |
| `axis_source` | ось, ось-источник, порядок | Откуда созданная сущность перенимает значение оси от другой сущности (место экземпляра, созданного из другого) |
| `kind` | справочник, название, порядок, значение «из», значение «в», признак «проверка», признак «вес 0», примечание к «вес 0» | Вид перехода; ось и сущность определяются значениями |
| `kind_condition` | вид перехода, значение | Строка условия: сущность, ось, значение (сущность и ось определяются значением). Все строки вида выполняются вместе; оси условия переходом не меняются |
| `executor` | справочник, название, порядок | Исполнитель |
| `instrument` | справочник, название, порядок | Инструмент |
| `scope` | справочник, название, порядок, признак «на пачку» | Охват |
| `variant_param` | справочник, название, порядок | Параметр варианта; его значение — исполнитель справочника |
| `named_slice` | справочник, название, порядок | Именованный срез, заданный условием. Начальный и конечный заданы местом в варианте, есть всегда и строками не хранятся |
| `named_slice_term` | именованный срез, номер группы, значение, параметр варианта, исполнитель | Строка условия среза: либо сущность, ось, значение (заполнено значение), либо параметр варианта и исполнитель. Внутри группы — все строки вместе («И»); между группами — «ИЛИ» |

Условие среза из групп нужно по факту: «сдано бухгалтеру» — это «экземпляр документа у бухгалтера **или** запись в учётной системе существует», а экземпляр «у получателя» считается у бухгалтера, только когда получатель — бухгалтер. Поэтому группа вида «Бумага: место = у получателя» **и** «получатель = бухгалтер».

Нормировка (одна на справочник, поэтому отдельной таблицы нормировки нет: строки ссылаются прямо на виды, исполнителей, охваты и оси):

| Таблица | Поля | Смысл |
|---|---|---|
| `norm_kind_cost` | вид перехода, стоимость в нажатиях, примечание | Строка на каждый вид без признака «вес 0»; у вида с «вес 0» строки нет, его стоимость 0 |
| `norm_executor` | исполнитель, коэффициент | Человек 1, программа или служба 0 |
| `norm_scope` | охват, коэффициент | Число на каждый охват справочника; задаёт пользователь |
| `norm_skip_price` | ось проверки, цена пропуска | 1 или 3 |

Стороны и пути:

| Таблица | Поля | Смысл |
|---|---|---|
| `side` | проект, роль («мы» или «они»), подпись | Ровно две строки на проект, создаются вместе с проектом |
| `path` | сторона, код, название, порядок, причина «вне сравнения» (пусто — вариант сравнивается) | Вариант пути; код не повторяется в проекте |
| `path_entity` | путь, сущность | Состав сущностей варианта; если строк нет — все сущности справочника |

| `path_param` | путь, параметр варианта, исполнитель | Кто занимает роль в этом варианте; задаётся для каждого параметра |
| `path_step` | путь, порядок, вид перехода, исполнитель, инструмент, охват | Переход в варианте |

Таблиц 24.

Числа (стоимость, коэффициент, цена) хранятся десятичной записью, не числом с плавающей точкой.

Чего в таблицах сознательно нет:

- признака «ось проверки» у оси: ось проверки — ось, которую меняет вид с признаком «проверка»;
- признака «человек» у исполнителя: человек — тот, у кого коэффициент больше нуля;
- отдельной таблицы нормировки: нормировка одна на справочник.

## 3. Загрузка файлами

### 3.1. Что грузится

Формат — JSON, как сейчас. Видов файла четыре:

| Файл | Содержит | Куда грузится |
|---|---|---|
| Справочник | определения, ось наличия, сущности с осями и значениями, виды переходов с условиями и признаками «проверка» и «вес 0», исполнители, инструменты, охваты с признаком «на пачку», параметры вариантов, именованные срезы с условиями | В проект; заменяет справочник проекта |
| Нормировка | стоимости видов переходов с примечаниями, коэффициенты исполнителей, коэффициенты охватов, цены пропусков | В проект; заменяет нормировку проекта |
| Пути | сторона, варианты: код, название, переходы, состав сущностей, отклонения начального среза, значения параметров, причина «вне сравнения» | В сторону проекта; добавляет варианты или заменяет варианты с тем же кодом |
| Проект целиком | всё перечисленное и перечень ошибок без оси в одном файле | Создаёт новый проект; им же проект выгружается |

Названия в файлах — словами, как сейчас (не номерами): файл читается и правится человеком. Строка условия в файле — тройка «сущность, ось, значение», как сейчас в `requires`; у среза строка может быть и парой «параметр варианта, исполнитель».

### 3.2. Соотношение с нынешними файлами

Сейчас один файл содержит и справочник, и числа, и варианты. Факты о нынешних данных:

- файл справочника: 9 сущностей, 28 осей, 31 вид перехода, вариантов нет;
- файл наших путей: 11 вариантов, 182 перехода, внутри — своя копия справочника, 34 вида переходов;
- файл путей конкурентов: 32 варианта, 491 переход, внутри — копия справочника, тождественная копии из файла наших путей;
- копия справочника в файлах путей расходится с файлом справочника (31 вид против 34, часть названий другая): пути ещё не переведены на новый справочник.

Что меняется в формате:

| Сейчас | В новом формате |
|---|---|
| Справочник повторён в каждом файле путей | Справочник — один файл; файл путей содержит только варианты |
| У вида перехода `cost` | Стоимость вида в файле нормировки |
| У вида перехода `zero_weight`, `zero_weight_note` | Остаются у вида в справочнике: признак «вес 0» и примечание; стоимость такого вида 0, в нормировку не вносится |
| У вида перехода `instrument_costs` | Не переносится (раздел 1) |
| У вида перехода `check` | Остаётся у вида в справочнике: признак «проверка» |
| У исполнителя `factor` | Коэффициент в файле нормировки |
| `batch_scope` | Признак «на пачку» у охвата в справочнике; коэффициент каждого охвата — число в файле нормировки |
| `named_slices` — именованные срезы с условием группами (`states`, `params`); `texts.named_slices` — их текст | Перечень именованных срезов в справочнике, условие — строками: группа из `states` и `params` даёт строки одной группы. «Сдано бухгалтеру» — девять групп через «ИЛИ»: четыре группы «сущность: место = у бухгалтера» и четыре группы «сущность: место = у получателя» и «получатель = бухгалтер» (для сущностей «Бумага», «Файл поставщика», «Изображения», «Файл документа»), одна группа «Запись в учётной системе: наличие = существует». Начальный и конечный не записываются: они есть всегда. Пояснение «смысл» переходит в текст определений |
| `variant_params` — перечень параметров варианта | Параметры варианта в справочнике |
| `forbidden_words`, `forbidden_exceptions`, `texts.title`, `texts.header`, `texts.split_semantic`, `texts.variants_note` | Не переносятся; `texts.definitions` — текст определений справочника |
| Стороны нет: «мы» и «они» — два разных файла | Сторона указана в файле путей |
| `params` у варианта — `{параметр: исполнитель}` | Значение каждого параметра указывается у пути |

Приложение принимает и файл старого вида: справочник из него загружается как справочник (признаки `check` и `zero_weight` остаются у вида), варианты — как пути выбранной стороны. Именованные срезы и параметры вариантов берутся из `named_slices`, `variant_params` и `params`; текст `texts.named_slices` программой не разбирается. Если этих полей в файле старого вида нет, именованные срезы и параметры вариантов не создаются, это называется в списке предупреждений; они вносятся с экрана или файлом справочника нового вида. Если в проекте справочник уже есть, копия справочника в файле путей сравнивается с ним; при расхождении загрузка отклоняется со списком расхождений.

### 3.3. Проверки при загрузке

Файл загружается целиком или не загружается вовсе. При отказе показывается полный список ошибок, а не первая. Каждая ошибка называет место: вид перехода, или вариант и номер перехода.

Справочник:

- названия не повторяются: сущности; оси в сущности; значения в оси; виды переходов; исполнители; инструменты; охваты; параметры вариантов; именованные срезы;
- у оси есть хотя бы одно значение;
- вид перехода ссылается на существующие сущность, ось и оба значения; «из» не равно «в»;
- строка условия вида перехода ссылается на существующие сущность, ось и значение и не на собственную ось вида;
- признак «на пачку» стоит не больше чем у одного охвата;
- источник начального значения существует;
- у оси наличия есть значение «не существует»;
- нет двух видов с одинаковой четвёркой «сущность, ось, из, в»;
- ни один вид не повторяется цепочкой из других видов по той же оси (иначе один и тот же сдвиг можно записать двумя способами);
- строка условия именованного среза ссылается на существующие сущность, ось и значение либо на существующие параметр варианта и исполнителя.

Нормировка:

- все названия есть в справочнике проекта;
- стоимость — число не меньше нуля; коэффициент исполнителя и коэффициент охвата — числа не меньше нуля; цена пропуска — число больше нуля;
- стоимость не задана для вида с признаком «вес 0»;
- цена задана только для осей проверки.

Неполная нормировка загружается; чего в ней не хватает, показывается списком, и варианты, которым не хватает чисел, получают в сравнении «не задано» вместо результата.

Пути:

- код варианта не повторяется в проекте;
- вид перехода, исполнитель, инструмент, охват, сущности состава, значения отклонений и параметры варианта есть в справочнике;
- у варианта задано значение каждого параметра варианта, и это исполнитель справочника;
- причина «вне сравнения», если указана, — непустой текст;
- прогон: сущность перехода входит в состав варианта; текущее значение оси равно «из» вида перехода; условие вида выполнено в текущем срезе. Сообщение: вариант, номер перехода, вид, что ожидалось и что есть.

Если справочник заменён или изменён, когда пути уже есть, все пути прогоняются заново; путь с ошибкой остаётся в базе с пометкой «с ошибкой» и в сравнение не идёт. Удаление из справочника того, что используется в путях или нормировке, отклоняется со списком мест.

## 4. Экран

Окно одно. Сверху — выбор проекта, ниже четыре вкладки в порядке работы: Справочник, Нормировка, Пути, Сравнение.

### 4.1. Проекты

Список проектов. Действия: создать пустой, загрузить из файла проекта, выгрузить в файл, скопировать, удалить (с подтверждением).

### 4.2. Справочник

- Слева дерево: сущность → оси → значения. Порядок меняется перетаскиванием; первое значение — начальное. У оси созданной сущности — источники начального значения.
- Справа списки: виды переходов (название, сущность, ось, из, в, условие — строки «сущность, ось, значение», всё выбором из списков, не набором текста; галочки «проверка» и «вес 0», примечание к «вес 0»), исполнители, инструменты, охваты (галочка «на пачку»), параметры вариантов, именованные срезы (название и условие: группы строк «сущность, ось, значение» или «параметр варианта, исполнитель»; между группами «ИЛИ»).
- Текст определений проекта.
- Кнопки «Загрузить из файла», «Выгрузить в файл».
- Внизу — список ошибок справочника и счёт: сущностей, осей, значений, видов переходов; виды переходов и исполнители, не использованные ни в одном пути.

### 4.3. Нормировка

- Действия: загрузить из файла, выгрузить в файл.
- Четыре таблицы, строки которых берутся из справочника, вводятся только числа:
  - виды переходов: стоимость в нажатиях, примечание; вид с признаком «вес 0» показан со стоимостью 0 без ввода;
  - исполнители: коэффициент;
  - охваты: коэффициент;
  - оси проверки: цена пропуска.
- Незаполненные ячейки выделены; число незаполненных показано.

### 4.4. Пути

- Слева список вариантов в двух группах — «мы» и «они»; у варианта с ошибкой пометка. Действия: новый, копия (варианты часто отличаются несколькими переходами), удалить, загрузить из файла, выгрузить.
- Справа выбранный вариант:
  - код, название, сторона, галочка «вне сравнения» с причиной;
  - значения параметров варианта (выбор исполнителя для каждого параметра);
  - состав сущностей (галочки; по умолчанию — все сущности справочника) и отклонения начального среза;
  - таблица переходов: номер, вид, исполнитель, инструмент, охват, и что изменилось («ось: из → в»);
  - под таблицей — срез после выбранной строки: сущности и значения осей, изменившееся значение выделено.

Ввод варианта с экрана:

1. Заполняются код, название, сторона, значения параметров варианта. Показывается начальный срез.
2. Кнопка «Добавить переход». В списке видов переходов показаны только те, что разрешены из текущего среза: текущее значение оси равно «из», условие выполнено. Остальные виды видны отдельно серым, с причиной, почему не разрешены.
3. Выбираются вид, исполнитель, инструмент, охват. Исполнитель, инструмент и охват по умолчанию — как в предыдущей строке.
4. Строка добавляется, срез пересчитывается и показывается.
5. Строку можно вставить в середину, удалить, передвинуть. После этого вариант прогоняется заново; первая строка, которая перестала проходить, выделяется с сообщением. Вариант с ошибкой можно сохранить и доделать позже; в сравнение он не идёт.

### 4.5. Сравнение

Таблица, строка — вариант:

| Столбец | Содержание |
|---|---|
| Сторона | «мы» или «они» |
| Код, название | — |
| Переходов | число переходов варианта |
| Труд: по одному столбцу на каждого исполнителя с коэффициентом больше нуля | нажатий |
| Труд вместе | сумма столбцов труда |
| Пропуски на каждом именованном срезе, заданном условием (сейчас — «сдано бухгалтеру») | сумма цен пропусков |
| Пропуски на конечном срезе | сумма цен пропусков |

- Сортировка по любому столбцу; по умолчанию — по труду вместе, от меньшего. Отбор по стороне.
- Варианты «вне сравнения» — отдельной таблицей ниже, с причиной; в сортировке основной таблицы не участвуют.
- Варианты с ошибкой и варианты, которым не хватает чисел нормировки, — списком ниже с причиной.
- Ниже — перечень ошибок без оси, текстом, как введён; правится здесь же. В итог не входит.
- Щелчок по строке открывает подробности варианта:
  - таблица переходов: вид, исполнитель, охват, стоимость × коэффициент охвата × коэффициент исполнителя = труд перехода;
  - номер перехода, после которого наступает каждый именованный срез, или «совпадает с конечным»;
  - список пропусков на каждом из двух срезов: ось проверки и цена.
- Кнопка «Выгрузить»: та же таблица, перечень ошибок без оси и подробности в файл Markdown и в CSV.

## 5. Счёт

Обозначения: у варианта переходы 1…n; срез 0 — начальный, срез i — после перехода i, срез n — конечный.

### 5.1. Срезы

- Начальный срез: каждая ось сущности варианта получает первое значение; отклонения варианта заменяют его указанными значениями. У несуществующей сущности значение имеет только ось наличия.
- Вид перехода меняет значение одной оси одной сущности: было «из», стало «в». Больше ничего при переходе не меняется. У вида может быть условие: переход возможен, только если названные в условии оси уже имеют названные значения. Сами эти оси остаются как были.
- При создании сущности (ось наличия уходит со значения «не существует») остальные её оси, у которых до того значений не было, получают начальные значения: перенимают значение от другой сущности — от первого источника, у которого значение есть, иначе первое значение оси. Это начальные значения, а не изменение значений.
- При уничтожении сущности остальные её оси теряют значения.

### 5.2. Труд

- Труд перехода = стоимость вида перехода × коэффициент охвата × коэффициент исполнителя. Коэффициент охвата — число из нормировки для охвата этого перехода; приложение только перемножает. Единица — нажатие.
- У вида с признаком «вес 0» стоимость 0.
- Пример: вид стоимостью 2, охват с коэффициентом 0,01, исполнитель с коэффициентом 1: 2 × 0,01 × 1 = 0,02.
- Итог пути — отдельно по каждому исполнителю с коэффициентом больше нуля (сумма труда его переходов) и вместе (сумма по всем переходам варианта).
- Столбец в сравнении получает каждый исполнитель с коэффициентом больше нуля, у которого есть хотя бы один переход в показанных вариантах.
- Счёт ведётся точными дробями; печатается с двумя знаками после запятой, в подробностях — без округления.
- Если переходу не хватает числа (стоимости, коэффициента исполнителя или коэффициента охвата), труд варианта не считается: печатается «не задано» и перечень недостающего.

### 5.3. Пропуски

- Именованный срез, заданный условием, в варианте — первый по порядку срез, в котором выполнено его условие (все строки хотя бы одной группы; строка «параметр варианта, исполнитель» выполнена, если в варианте этот параметр занимает этот исполнитель). Если такого среза нет, именованный срез совпадает с конечным. Он есть в каждом варианте, пропуски на нём считаются всегда.
- Пропуск на срезе — ось проверки, значение которой в этом срезе равно начальному значению оси.
- Итог на срезе = сумма цен пропусков; рядом список пропусков.
- Считается на каждом именованном срезе проекта, заданном условием, и на конечном срезе. Исполнитель и охват в этот счёт не входят.
- Если у оси проверки нет цены, итог — «не задано» с перечнем таких осей; список пропусков печатается всё равно.
- Ошибки без оси в счёт не входят: их перечень показывается в сравнении отдельно.

### 5.4. Что печатается

Сравнение (раздел 4.5) на экране и в выгрузке; подробности варианта; перечень ошибок без оси; при загрузке — список ошибок. Больше ничего.

Наполнение настоящими данными (справочник, нормировка, 43 пути) — после части 2: расчёт уже можно получить командой, не дожидаясь окна.

## 10. Решено без вопроса

- У вида с признаком «вес 0» стоимость в нормировку не вносится: она 0.
- Значение каждого параметра варианта у варианта обязательно.
- При создании сущности остальные её оси получают начальные значения; это не изменение значений, у несуществующей сущности их не было.
- Текст `texts.named_slices` программой не разбирается; именованные срезы и параметры вариантов берутся из `named_slices`, `variant_params` и `params`, а если их в файле старого вида нет, вносятся отдельно.
- Результаты расчёта в базе не хранятся.
- Стороны ровно две; продукт конкурента остаётся в названии варианта.
- Файл загружается целиком или не загружается; ошибки — полным списком.

## 11. Вопросы заказчику

Решены:

- **process-6.** Справочник в проекте один; попробовать другой справочник — значит скопировать проект. Решение: один справочник на проект.
- **process-7.** Решение: нормировка одна на справочник.
- **process-8.** Раздел чисел и справочника. Решение: в справочнике — признаки «проверка» и «вес 0» (с примечанием) у вида перехода, признак «на пачку» у охвата; в нормировке — стоимость вида перехода, коэффициент исполнителя, коэффициент охвата, цена пропуска по оси проверки.
- **process-9.** Решение: труда на документ нет. Труд перехода = стоимость вида × коэффициент охвата × коэффициент исполнителя, в нажатиях; итог пути — по каждому исполнителю с коэффициентом больше нуля и вместе.
- **process-10.** Решение: Python, окна PySide6, база SQLite одним файлом, готовые сборки для Windows и Linux.
- **process-12.** Решение: окно — на английском; описание — на английском и на русском.
- **process-13.** Решение: лицензия GPL v3 (GPL-3.0-or-later); автор — Ilia Tsigelnitskii.

Открыты:

- **process-11.** Пример со счетами в публичном репозитории. Предложение: первая публикация — только с нейтральным примером (вариант «а»); пример со счетами готовится отдельным файлом и добавляется отдельным решением после правки путей, тогда же выбирается «б», «в» или «г».
