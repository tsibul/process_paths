1# Measure Twice: six prompts for an AI chat# Measure Twice: шесть просьб для чата с AI
2The person talks to an AI chat (ChatGPT, Gemini) in six steps and only copies the prompts below. Each step is one prompt; the person adds at most a sentence or two, then answers the AI's "Points to check" with "yes" or a correction in words. The format is needed only at step 5. Step 6 is built by the program when it refuses the file; it is used again until the file loads.Человек говорит с чатом AI (ChatGPT, Gemini) в шесть шагов и только копирует просьбы ниже. Каждый шаг — одна просьба; человек добавляет не больше одной-двух фраз, а на «Что проверить» отвечает «да» или поправкой своими словами. Формат нужен только на шаге 5. Шаг 6 строит программа, когда не принимает файл; он повторяется, пока файл не загрузится.
3## Prompt 1. Task## Просьба 1. Задача
4Use it first, in a new chat. Replace {task} with one or two sentences about the task.Первой, в новом чате. Вместо {task} — одна-две фразы о задаче.
5```text We will prepare a file for Measure Twice, a program that compares ways of doing one task by labour. We go in six steps; I will give you a prompt for each. Rules for the whole conversation: - Do each step yourself. Do not stop to ask me questions. Where unsure, take the likely answer. - End every answer with "Points to check": 2-4 numbered doubtful places. I answer "yes" or correct them in words. - Propose numbers yourself and mark the doubtful ones. - Use the language of my task for all text and names. - Write no file until step 5.```text Мы подготовим файл для Measure Twice — программы, которая сравнивает пути выполнения одной задачи по труду. Идём в шесть шагов; на каждый я дам просьбу. Правила на весь разговор: - Каждый шаг делай сам. Не останавливайся, чтобы задать мне вопросы. Если не уверен, бери вероятный ответ. - Каждый ответ заканчивай разделом «Что проверить»: 2-4 пронумерованных сомнительных места. Я отвечаю «да» или поправляю словами. - Числа предлагай сам и помечай сомнительные. - Все тексты и названия пиши на языке моей задачи. - До шага 5 файл не пиши.
6Step 1. Task. My task: {task}Шаг 1. Задача. Моя задача: {task}
7Give the task one short name; all ways share it. List the ways to do it that you understood from my words: a short title, one line on what is done, and "own" (mine) or "other" (someone else's). Then add the usual ways I did not mention: only ways that really solve the task, always "other". End the title of each added way with "(added)" and keep it through our conversation and in the file; action names get no mark. An added way must differ from the others in its actions. In "Points to check" name each added way and ask which ways are missing or extra. ```Дай задаче одно короткое название; оно общее для всех путей. Перечисли пути её выполнения, которые ты понял из моих слов: короткое название, одна строка о том, что делается, и «свой» (мой) или «чужой» (чей-то ещё). Затем добавь обычные пути, о которых я не сказал: только те, что правда решают задачу, всегда «чужой». Название каждого добавленного пути заканчивай пометкой «(добавлен)» и сохраняй её весь разговор и в файле; у названий действий пометки нет. Добавленный путь должен отличаться от других действиями. В «Что проверить» назови каждый добавленный путь и спроси, каких путей не хватает и какие лишние. ```
8## Prompt 2. Steps## Просьба 2. Шаги
9Use it when the list of ways is agreed.Когда список путей согласован.
10```text Step 2. Steps. Write every agreed way out step by step. I give you no steps: write them yourself, as the work is really done. - Include the routine steps: prepare (shut off the water or power), check the result, clean up. - One step is one action, in plain words. Say who does it. - A way that hands the work to someone (a hired worker, a service) lists that worker's steps. - If two ways reach the same result differently, say which part each step works on (replace the washer, tighten the nut, tape the thread), not just "fix it". - A way without a check gets no step for it, not even "no check is made". - Mark each step where the person only waits (for a plumber, for a delivery) and give a rough duration. - In "Points to check" name, in one point, the steps you added that are not in my words. Show a numbered list per way. No file format yet. End with "Points to check": the 2-4 steps you are least sure of. ``````text Шаг 2. Шаги. Распиши каждый согласованный путь по шагам. Шагов я не даю: напиши их сам, как работа делается на самом деле. - Включи обычные шаги: подготовку (перекрыть воду, отключить ток), проверку результата, уборку. - Один шаг — одно действие, простыми словами. Скажи, кто его делает. - Путь, где работу отдают кому-то (наёмному работнику, службе), перечисляет шаги этого работника. - Если два пути приходят к одному результату по-разному, скажи, над какой частью работает каждый шаг (заменить прокладку, подтянуть гайку, обмотать резьбу), а не просто «починить». - У пути без проверки нет шага для неё, даже «проверка не делается». - Отметь каждый шаг, где человек только ждёт (сантехника, доставку), и дай примерную длительность. - В «Что проверить» одним пунктом назови шаги, которые ты добавил и которых нет в моих словах. Покажи пронумерованный список для каждого пути. Формата файла пока нет. В конце — «Что проверить»: 2-4 шага, в которых ты меньше всего уверен. ```
11## Prompt 3. Same actions and checks## Просьба 3. Одинаковые действия и проверки
12Use it when the steps are agreed.Когда шаги согласованы.
13```text Step 3. Same actions and checks. Go over the steps of all ways together. 1. The same action gets the same name in every way, word for word. 2. For each action say what it changes: one attribute of one thing, from one state to another. Example: "Replace the washer: Washer, worn -> new". 3. Two actions must never make the same change. Different ways to one result act on different parts: Washer, worn -> new; Nut, loose -> tight. 4. An action with no change of its own gets a new attribute (Floor: wet -> dry). Never hang it on another thing's change. Only work without labour is "no labour". 5. Mark the checks: a check confirms the result after an action, and skipping it has a price. If my words call an action a check, it is a check. Otherwise finding the cause of a fault is an ordinary action. A check changes an attribute of its own, not the state it looks at: "Test for leaks: Tap, leak not tested -> tested", "Inspect the seal: Washer, not inspected -> inspected". A way without a check gets no step for it; the thing still has the check attribute, so the skip shows. 6. Say what appears or disappears along the way (a bucket put under, a visit booked). A part that leaves with another thing gets its own no-labour action: make the same thing absent with its exists attribute (Washer: exists yes -> no, thrown away with the old tap); never add a new thing for the old part. Its checks are then not skipped. 7. Waiting for someone is its own kind of action: not a check, not labour. It still changes an attribute of its own (Plumber visit: booked -> done). Then run each way: every action starts from the state the previous one left. Fix any that does not. Show a table: action | thing | attribute | from -> to | check. Then each way as action names. End with "Points to check". ``````text Шаг 3. Одинаковые действия и проверки. Пройди по шагам всех путей вместе. 1. Одно и то же действие называется одинаково во всех путях, слово в слово. 2. Для каждого действия скажи, что оно меняет: один признак одной вещи, из одного состояния в другое. Пример: «Заменить прокладку: Прокладка, изношена -> новая». 3. Два действия никогда не делают одну и ту же смену. Разные способы прийти к одному результату действуют на разные части: Прокладка, изношена -> новая; Гайка, ослаблена -> затянута. 4. Действию без своей смены дай новый признак (Пол: мокрый -> сухой). Никогда не вешай его на смену другой вещи. «Без труда» — только работа, где труда нет. 5. Отметь проверки: проверка подтверждает результат после действия, и у её пропуска есть цена. Если в моих словах действие названо проверкой, это проверка. Иначе поиск причины поломки — обычное действие. Проверка меняет свой признак, а не то состояние, на которое смотрит: «Проверить на течь: Кран, течь не проверена -> проверена», «Осмотреть уплотнение: Прокладка, не осмотрена -> осмотрена». У пути без проверки нет шага для неё; признак проверки у вещи всё равно есть, поэтому пропуск виден. 6. Скажи, что появляется или исчезает по ходу (подставленное ведро, записанный визит). Часть, которая уходит вместе с другой вещью, получает своё действие без труда: сделай ту же вещь отсутствующей признаком наличия (Прокладка: наличие да -> нет, выброшена со старым краном); никогда не заводи новую вещь для старой части. Тогда её проверки не пропущены. 7. Ожидание кого-то — отдельный вид действия: не проверка и не труд. Оно тоже меняет свой признак (Визит сантехника: записан -> состоялся). Затем прогони каждый путь: каждое действие начинается из состояния, которое оставило предыдущее. Исправь те, что не сходятся. Покажи таблицу: действие | вещь | признак | из -> в | проверка. Затем каждый путь как названия действий. В конце — «Что проверить». ```
14## Prompt 4. Who and how much## Просьба 4. Кто и сколько
15Use it when the actions and checks are agreed.Когда действия и проверки согласованы.
16```text Step 4. Who and how much. 1. List the executors: who or what does the actions. 2. Give each a coefficient: how much of their labour counts, 1 for the main person. Coefficient 0 only for a machine or program that works by itself. Never 0 for a person, a hired one included. Put every coefficient 0 into "Points to check". 3. Give each action a labour cost in one unit for the whole project (minutes or points). Paying is not labour: no action for it. Waiting for someone is an action with a duration in hours or days, not a cost or weight: mark each with "?". A short wait with no duration needed (water draining) costs 0. 4. Say whether each action is done once for the whole job or for each unit; if per unit, how many units a batch has. 5. For each check give the price of skipping it, more than 0, in the labour unit, comparable to the work of fixing what the skip lets through. Never add it to labour. 6. Show the total of each way: sum of cost x executor coefficient x scope coefficient. If steps not in my words change a way's total noticeably, say so in "Points to check". Mark doubtful numbers with "?". End with "Points to check". ``````text Шаг 4. Кто и сколько. 1. Перечисли исполнителей: кто или что делает действия. 2. Дай каждому коэффициент: какая доля его труда засчитывается, 1 — для главного человека. Коэффициент 0 — только для машины или программы, которая работает сама. Никогда не 0 для человека, наёмного тоже. Каждый коэффициент 0 вынеси в «Что проверить». 3. Дай каждому действию стоимость труда в одной единице на весь проект (минуты или баллы). Оплата — не труд: действия для неё нет. Ожидание кого-то — действие с длительностью в часах или днях, а не со стоимостью или весом: пометь каждое знаком «?». Короткое ожидание, длительность которого не нужна (стекает вода), стоит 0. 4. Скажи, делается ли каждое действие один раз на всю работу или на каждую единицу; если на единицу — сколько единиц в пачке. 5. Для каждой проверки дай цену её пропуска, больше 0, в единице труда, сравнимую с работой по исправлению того, что пропуск пропустит. Никогда не прибавляй её к труду. 6. Покажи итог каждого пути: сумма стоимость x коэффициент исполнителя x коэффициент охвата. Если шаги не из моих слов заметно меняют итог пути, скажи об этом в «Что проверить». Сомнительные числа пометь знаком «?». В конце — «Что проверить». ```

20FORMAT A reference is the declared name letter for letter. Numbers are JSON numbers. Order matters. No name repeats in one list.
